# ADR 0004: REST и OpenAPI как API-контракт

- **Статус:** принято
- **Дата:** 31.08.2026

## Контекст

Web и API развиваются в одном monorepo, но должны иметь проверяемую границу. Контракт должен поддерживать версионирование и будущую генерацию client.

## Решение

Используем REST API с JSON и базовым префиксом `/api/v1`. OpenAPI документирует endpoint, request, response и ошибки. На Этапе 0 API публикует health paths, JSON и Swagger UI; frontend client не генерируется до появления продуктовых endpoint.

## Последствия

Изменения контракта можно проверять в CI. Breaking changes в `/api/v1` требуют миграционного плана. HTTP-контроллеры не содержат финансовых расчетов.

## Условия пересмотра

Решение пересматривается при доказанной необходимости другого протокола или несовместимых требований клиентов.

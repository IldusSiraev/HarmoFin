# ADR 0005: Представление денежных значений

- **Статус:** принято
- **Дата:** 31.08.2026

## Контекст

Ошибки округления недопустимы в семейном бюджете. JavaScript floating-point arithmetic не может быть источником истины для денежных сумм.

## Решение

Денежные сущности будут хранить integer minor units (`BIGINT`) вместе с валютой и scale. API будет принимать валидированные десятичные строки, а backend и PostgreSQL будут выполнять расчеты integer/decimal-safe внутри транзакций.

## Последствия

Frontend не рассчитывает и не подтверждает балансы. Форматирование суммы отделено от хранения. Полноценная мультивалютная конвертация не появляется простым снятием ограничения `RUB`.

## Условия пересмотра

Решение пересматривается отдельным migration plan при добавлении валют с иными правилами scale, курсов и переоценки.

# Инвентаризация legacy модели 1 после очистки (этап 08, C01–C05)

**Назначение**: зафиксировать фактическое состояние legacy-объектов модели 1 после задач C02c, C02/C02b, C03/C03c, C03b, C04, C02d и C05: что удалено, что осталось и почему, кто это читает. Документ ничего не удаляет и не заменяет `docs/runbooks/envelope-v2-cutover.md`. Он не утверждает, что cutover или restore выполнены.

**Дата среза**: 2026-10-03, ветка `feat/envelope-v22-foundation`. Метод: прямой content search (ripgrep) по `apps`, `e2e`, `prisma/schema.prisma`; SQL-миграции и документы не считались.

## Решение владельца и трактовка gate

- Решение владельца от 2026-10-03: модель 1 параллельно с моделью 2 не поддерживаем, активных пользователей кроме владельца нет, ненужный v1-код удаляем.
- Gate «нет бюджетов модели 1» трактуется так: релиз этой ветки выкатывается только по `envelope-v2-cutover.md`, cutover выполняется до запуска web/API/worker нового образа. В образе нет v1 API и v1 web; бюджет, не переведённый на модель 2, показывает сообщение вместо интерфейса, worker его пропускает.
- Нельзя удалять без отдельной утверждённой contract-миграции с backup: legacy таблицы и колонки схемы (никаких DROP), `FinancialBalanceRepository.accountBalance` с `transfer_parts`, исторические читатели (см. таблицу).
- Cutover на момент среза в журнале как выполненный не записан, поэтому код одноразового cutover остаётся.

## Статусы

| Статус                                  | Значение                                                                                          |
| --------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `active v2`                             | Нужно живому v2-пути, не удалять.                                                                 |
| `historical read`                       | Читает реальную историю эпохи модели 1; есть тест сохранения чтения.                              |
| `migration-only until cutover executed` | Нужен только одноразовому cutover; удалить после его фактического выполнения.                     |
| `только история/backup`                 | Объект схемы хранит данные эпохи модели 1; v2 не пишет в него новых строк; DROP только в backlog. |
| `удалено`                               | Код удалён в указанной задаче, потребителей нет.                                                  |

## Доказательства

- `apps/api/test/v2-historical-reads.integration.test.ts` (C01): бюджет модели 2 с историей модели 1 (income, expense, подтверждённый legacy-перевод с частью, legacy `income_allocation`) плюс v2 расход и прямой перевод. Журнал, `transfers`, отчёты, CSV, `history/legacy-assignments`, audit и `accountBalance` читают каждую старую сумму ровно один раз; общий cash не меняется от чтений.
- `apps/api/test/v2-legacy-boundary.integration.test.ts` (C05): в бюджет модели 2 с legacy-строками (подтверждённые `transfer_parts`, `income_allocations`, `envelope_reallocations`, `envelopes.starting_balance_minor`) выполняются v2 расход, v2 доход, прямой перевод `ACCOUNT_ONLY`, шаблон (preview и apply), funding preview и confirm, assignment, movement. Счётчики `transfer_parts`, `income_allocations`, `envelope_reallocations` и legacy-переводов не меняются, `FREE_MONEY` конвертов нет, `starting_balance_minor` legacy-конверта не изменён, новые конверты создаются с нулём. Legacy-строки продолжают отражаться в cash счетов (`accountBalance`), журнале, переводах, архиве назначений, CSV и audit.
- Тесты контракта: `apps/api/test/v2-openapi.integration.test.ts` проверяет отсутствие удалённых `/api/v1` путей и HTTP 404 на них.

## Backlog: поздняя contract migration

Не входит в v2.2. Выполняется только по отдельному утверждённому плану, **после backup** (с проверенным восстановлением) и **после доказательства отсутствия потребителей** (поиск по коду, OpenAPI, экспорту, отчётам, audit; решение владельца). DROP-команд в этом этапе нет и быть не должно. Кандидаты:

- таблицы `transfer_parts`, `income_allocations`, `envelope_reallocations` и значение `LEGACY_PARTS` режима перевода (вместе с переносом истории в неизменяемый архив или экспорт);
- колонка `envelopes.starting_balance_minor`, значение `FREE_MONEY` в `EnvelopeType`;
- `budgets.plan_model_version`, `plan_model_activated_on`, `transactions.accounting_model_version` (после того как не останется бюджетов и фактов модели 1 либо их история будет перенесена);
- код: `PlanModelPolicy` и `forceBudgetV1`, `reports/legacy-assignment-history.*`, `legacy-assignments.csv`, `LegacyAssignmentsArchive`, ветки `LEGACY_PARTS` в `accountBalance`, `v2-transfers` и `legacy-correction`.

Условие для кода cutover: `apps/api/src/migrations/envelope-v2/*` и `legacy-envelope-balance.ts` удаляются сразу после фактического выполнения cutover (отдельно от contract migration схемы).

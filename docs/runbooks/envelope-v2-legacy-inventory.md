# Инвентаризация legacy-кода модели 1 перед удалением (этап 08, C01)

**Назначение**: перед удалением v1-кода зафиксировать, кто ещё читает или пишет legacy-объекты. Документ ничего не удаляет и не отменяет `docs/runbooks/envelope-v2-cutover.md`.

**Дата среза**: 2026-10-03, ветка `feat/envelope-v22-foundation`. Метод: прямой content search (ripgrep) по `apps`, `e2e`, `prisma/schema.prisma`; SQL-миграции и документы не считались.

## Решение владельца и трактовка gate

- Решение владельца от 2026-10-03: v1 параллельно с v2 не поддерживаем, активных пользователей кроме владельца нет, ненужный v1-код удаляем.
- Gate «нет бюджетов модели 1» трактуется так: релиз этой ветки выкатывается только по `envelope-v2-cutover.md`, cutover выполняется до запуска web/API/worker нового образа. Поэтому v1-пути в новом образе не нужны.
- Нельзя удалять: (а) legacy таблицы и колонки схемы (никаких DROP); (б) `FinancialBalanceRepository.accountBalance` с legacy `transfer_parts`; (в) всё, что нужно одноразовому cutover до его фактического выполнения (`apps/api/src/migrations/envelope-v2/*`). Такие места помечены «migration-only until cutover executed».
- Cutover на момент среза не выполнен (в журнале нет записи о выполнении), поэтому всё, что читает preflight, остаётся.

## Статусы

| Статус                                  | Значение                                                                      |
| --------------------------------------- | ----------------------------------------------------------------------------- |
| `active v2`                             | Нужно живому v2-пути, не удалять.                                             |
| `historical read`                       | Читает реальную историю эпохи v1; нужен тест и цель сохранения.               |
| `migration-only until cutover executed` | Нужен только одноразовому cutover; удалять после его фактического выполнения. |
| `dead code`                             | Нет потребителя после cutover; удаляется в указанной задаче.                  |

## Доказательство историчности чтений

Тест `apps/api/test/v2-historical-reads.integration.test.ts` (на disposable БД, 7 тестов) строит бюджет v2 с историей v1-эпохи (income и expense с `accounting_model_version=1`, подтверждённый legacy-перевод с частью, legacy `income_allocation`) плюс v2 расход и прямой перевод `ACCOUNT_ONLY`. Он доказывает, что каждая старая сумма читается ровно один раз:

- журнал `GET /api/v2/budgets/:id/transactions` (старые id, модель 1, суммы);
- `GET /api/v2/budgets/:id/transfers` и `/transfers/:id` (legacy-перевод с `parts` и прямой перевод);
- отчёты `account-balances`, `net-cash-flow`, `expenses-by-category`;
- CSV `transactions.csv` (старые id один раз, колонка «Модель» = 1) и `legacy-assignments.csv`;
- `GET /api/v2/budgets/:id/history/legacy-assignments` (legacy allocation);
- audit старой операции;
- `accountBalance` по счетам и общий cash `1 320 000` (старый allocation и переводы cash не меняют), cash не меняется после чтений.

**Найденный живой потребитель, доступный только через v1**: аудит транзакции `GET /api/v1/budgets/:budgetId/transactions/:transactionId/audit` (`apps/api/src/audit/audit.controller.ts`). Версионированного v2-аналога нет, маршрут не привязан к модели и работает на бюджете v2. Его нельзя удалять вместе с v1 контроллерами операций (C03c), web `OperationDrawer.vue` вызывает его через `listTransactionAudit`. Чтение legacy-переводов и legacy-распределений через v2-пути доступно, потребителей только через v1 нет.

## Ключевые находки

1. Все v1 сервисы финансовых записей уже отвечают `409 MODEL_VERSION_MISMATCH` на бюджет v2 через `requireModel(..., 1)`, но не все методы: чтения `GET` транзакций (`list`, `get`), переводов, распределений и планов (`list`, `get`, `occurrences`) не закрыты. Закрыты: все мутации, `envelopes` целиком, `dashboard /summary`, `reports`, `exports/transactions.csv`, `PATCH budgets`, `budgets/:id/reference-template`.
2. Web на бюджете v2 всё ещё ходит в v1: журнал операций (`pages/app/operations.vue`: `listTransactions`, `getTransaction`, `updateTransaction`, `getDashboardSummary`), `OperationDrawer.vue` (аудит, `createIncomeAllocation`), `useOperationMutations.ts` (confirm/cancel/delete/restore по v1). Закрытые v1 методы дадут 409. Web не вызывает `GET /api/v2/.../transactions` совсем (только `POST` через `useEnvelopePlanV2`). Это нужно проверить до C02b/C03c: если подтвердится, перед удалением v1 нужна замена потребителя (новая задача «журнал операций на v2 API»).
3. v2-код зависит от v1 файлов, которые удалять нельзя без выноса: `transactions/transaction.repository.ts` (используется `v2-transactions`, `obligations`, `plans/income-plan-v2`, `exports`), `allocations/income-allocation.repository.ts` (`v2-transactions/legacy-correction`), `plans/plan-occurrence.repository.ts` и `regular-plan.repository.ts` (v2 dashboard, funding, obligations), `budgets/budget.repository.ts` (`DEFAULT_CATEGORIES` в `v2-template`), `exports/csv-export.application.service.ts` (`encodeCsv`, `CsvExportResult` в v2 экспорте).
4. `preservePurpose`: совпадений в коде нет (поле уже отсутствует). `packages/` содержит только `eslint-config` и `tsconfig`, общих контрактов с v1-типами нет.
5. `FinancialBalanceRepository.envelopeBalance` читают: v1 репозитории (`envelopes`, `transactions`, `transfers`, `allocations`, `envelope-reallocations`, `dashboard`, `reports`), worker `notification.handler.ts` (своя копия SQL), preflight cutover. В v2-коде не читается.

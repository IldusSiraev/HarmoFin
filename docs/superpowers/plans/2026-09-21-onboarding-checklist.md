# Onboarding Checklist Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dashboard checklist that walks a brand-new HarmoFin user through the 5 setup steps (base template, financial cycle, accounts, envelope starting balances, first allocated income) with Russian-language explanations and deep links into the existing pages, computing every step's completion status on the server.

**Architecture:** Extend `GET /api/v1/budgets/:budgetId/summary` with a new `onboarding` object (4 server-computed booleans + 1 derived from already-fetched budget fields), change the `Budget.cycleStartDay` default from 10 to 1 (calendar month) so "cycle configured" has a real signal, and add a new `OnboardingChecklist.vue` component to the dashboard that reads that object and renders 5 status rows, one of which (step 1) calls the existing reference-template endpoint directly instead of navigating away.

**Tech Stack:** NestJS/Fastify + Prisma (raw `$queryRaw` for cross-table booleans, matching the existing `unassignedStartingBalance` pattern), Vue 3/Nuxt 4 SFC with `<script setup>`, Vitest for unit/component tests, Fastify `inject()` for integration tests, Playwright for e2e.

**Spec:** [docs/superpowers/specs/2026-09-21-onboarding-checklist-design.md](../specs/2026-09-21-onboarding-checklist-design.md)

## Global Constraints

- Money and completion-status calculations happen server-side only; the frontend never computes balances or step completion itself (CLAUDE.md financial correctness).
- Every query filters by `budgetId` in the database query itself (CLAUDE.md data isolation) — no fetch-then-filter.
- Only `CONFIRMED` transactions/allocations count toward `hasAllocatedIncome`.
- All new user-facing text is Russian; code identifiers stay English.
- `cycleStartDay` valid range is 1–28, `periodBoundaryOffset` is 1–27 (`apps/api/src/budgets/budget.schemas.ts:16-17`) — the new default (1, 15) must stay inside this range (it does).
- OpenAPI is the frontend/backend contract: after any DTO change, regenerate `openapi.json` with `node scripts/openapi/generate.mjs openapi.json` and commit it.
- Playwright e2e runs only in CI, not locally, per this project's established convention.
- Every task ends in a passing test run and its own commit; no task leaves `typecheck` broken.

```ts
async function onboardingStatus(
  tx: Prisma.TransactionClient,
  budgetId: string,
): Promise<{
  categoriesSeeded: boolean;
  hasAccounts: boolean;
  hasEnvelopeStartingBalances: boolean;
  hasAllocatedIncome: boolean;
}> {
  const rows = await tx.$queryRaw<
    Array<{
      categoriesSeeded: boolean;
      hasAccounts: boolean;
      hasEnvelopeStartingBalances: boolean;
      hasAllocatedIncome: boolean;
    }>
  >`
    SELECT
      (
        EXISTS(
          SELECT 1 FROM "categories"
          WHERE "budget_id" = ${budgetId}::uuid AND "archived_at" IS NULL
        )
        OR EXISTS(
          SELECT 1 FROM "envelopes"
          WHERE "budget_id" = ${budgetId}::uuid AND "archived_at" IS NULL
        )
      ) AS "categoriesSeeded",
      EXISTS(
        SELECT 1 FROM "accounts"
        WHERE "budget_id" = ${budgetId}::uuid AND "archived_at" IS NULL
      ) AS "hasAccounts",
      (
        COALESCE((
          SELECT SUM("starting_balance_minor")
          FROM "envelopes"
          WHERE "budget_id" = ${budgetId}::uuid AND "archived_at" IS NULL
        ), 0) <> 0
      ) AS "hasEnvelopeStartingBalances",
      EXISTS(
        SELECT 1
        FROM "income_allocations" AS allocation
        INNER JOIN "transactions" AS income
          ON income."id" = allocation."income_transaction_id"
          AND income."budget_id" = allocation."budget_id"
        WHERE allocation."budget_id" = ${budgetId}::uuid
          AND allocation."status" = 'CONFIRMED'
          AND income."status" = 'CONFIRMED'
      ) AS "hasAllocatedIncome"
  `;
  return (
    rows[0] ?? {
      categoriesSeeded: false,
      hasAccounts: false,
      hasEnvelopeStartingBalances: false,
      hasAllocatedIncome: false,
    }
  );
}
```

async function configureIncomeAllocationRule(page: Page): Promise<void> {
  await page.evaluate(async () => {
    const api = 'http://localhost:3001/api/v1';
    const me = (await fetch(`${api}/me`, { credentials: 'include' }).then((response) =>
      response.json(),
    )) as { workspaces: Array<{ budgets: Array<{ id: string }> }> };
    const budgetId = me.workspaces[0]?.budgets[0]?.id;
    if (!budgetId) throw new Error('Missing budget id');

    const categories = (await fetch(`${api}/budgets/${budgetId}/categories?type=INCOME`, {
      credentials: 'include',
    }).then((response) => response.json())) as Array<{ id: string; name: string }>;
    const envelopes = (await fetch(`${api}/budgets/${budgetId}/envelopes`, {
      credentials: 'include',
    }).then((response) => response.json())) as Array<{ id: string; name: string }>;
    const category = categories.find((item) => item.name === 'Премия');
    const envelope = envelopes.find((item) => item.name === 'Свободные');
    if (!category || !envelope) throw new Error('Missing template category or envelope');

    const csrf = (await fetch(`${api}/auth/csrf`, { credentials: 'include' }).then((response) =>
      response.json(),
    )) as { csrfToken: string };
    await fetch(`${api}/budgets/${budgetId}`, {
      method: 'PATCH',
      credentials: 'include',
      headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrf.csrfToken },
      body: JSON.stringify({
        incomeAllocationRuleEnabled: true,
        incomeAllocationSourceCategoryId: category.id,
        incomeAllocationTargetEnvelopeId: envelope.id,
      }),
    });
  });
}

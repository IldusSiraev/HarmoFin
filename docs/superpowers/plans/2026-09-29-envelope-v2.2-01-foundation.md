# HarmoFin: план реализации Envelope Plan v2.2 — 01. Совместимая основа

> **Для исполнителя:** одна задача за сессию, TDD, отчёт и стоп. Без субагентов/worktree. Использовать [индекс/контракты](2026-09-29-envelope-v2.2-00-roadmap.md) и [спецификацию, §2–4, §8, §12](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md). Чекбоксы отслеживают шаги.

**Цель:** Добавить версию модели, v2-маршруты и additive-хранилище без изменения работающего v1.

**Архитектура:** PostgreSQL по умолчанию создаёт бюджет модели 1, а новые v2-объекты пока доступны только тестовым бюджетам модели 2. В Nest используется URI versioning с v1 по умолчанию; таблицы v1 не удаляются. Чистые доменные формулы отделены от SQL.

**Стек:** Node.js 24.20.0, pnpm 11.24.0, NestJS 11/Fastify, Prisma/PostgreSQL 18, TypeScript strict, Vitest.

**Спецификация:** [v2.2](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md).

## Общие ограничения

- RUB/scale=2, `BIGINT`/`bigint`, только CONFIRMED; бюджеты v1 работают по-старому. Новые таблицы `budget_id` + составные FK. Локальные миграции — только изолированная тестовая БД.
- Русский текст ошибок; новая версия API не меняет существующие `/api/v1/*`. На этом этапе не переключать регистрацию/бюджеты на модель 2.
- Целевые тесты + `pnpm typecheck` перед узким коммитом; Playwright локально не запускать.

Фрагмент SQL ниже показывает обязательные CHECK/FK, а не полную Prisma migration: включить в неё все перечисленные поля/связи.

```sql
CREATE TABLE envelope_periods (
  id UUID PRIMARY KEY, budget_id UUID NOT NULL, envelope_id UUID NOT NULL,
  starts_on DATE NOT NULL, ends_on DATE NOT NULL, target_minor BIGINT,
  target_status VARCHAR(12) NOT NULL DEFAULT 'UNSET',
  confirmed_by_user_id UUID, confirmed_at TIMESTAMPTZ,
  UNIQUE (id, budget_id), UNIQUE (id, budget_id, envelope_id),
  UNIQUE (budget_id, envelope_id, starts_on),
  FOREIGN KEY (envelope_id, budget_id) REFERENCES envelopes(id, budget_id),
  CHECK (ends_on >= starts_on),
  CHECK ((target_status = 'UNSET' AND target_minor IS NULL)
      OR (target_status IN ('DRAFT','CONFIRMED') AND target_minor >= 0)),
  CHECK ((target_status = 'CONFIRMED' AND confirmed_by_user_id IS NOT NULL AND confirmed_at IS NOT NULL)
      OR (target_status <> 'CONFIRMED' AND confirmed_by_user_id IS NULL AND confirmed_at IS NULL))
);
```

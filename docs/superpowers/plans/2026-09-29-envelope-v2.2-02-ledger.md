# HarmoFin: план реализации Envelope Plan v2.2 — 02. Ledger назначений

> **Для исполнителя:** одна задача за сессию через субагентов, TDD, review, отчёт и стоп; без worktree. Читайте [индекс и порядок работы](2026-09-29-envelope-v2.2-00-roadmap.md), [спецификацию §3–5, §9–10](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md) и только свой Task.

**Цель:** Дать бюджету модели 2 реальные серверные вычисления виртуальных остатков, назначения из свободных/доходов и явные переносы без движения денег по счетам.

**Архитектура:** Репозиторий читает ledger и подтверждённые расходы модели 2 с фильтром бюджета/периода. Application services под бюджетной блокировкой проверяют физическую обеспеченность и источники, вызывают `IdempotencyService` и записывают audit. Старые таблицы остатков v1 не входят в новые проекции.

**Стек:** Node.js 24.20.0, pnpm 11.24.0, NestJS/Fastify, Prisma/PostgreSQL 18, Vitest, integer minor units.

**Спецификация:** [v2.2](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md).

### Задача L01: Бюджетная SQL-проекция остатка назначения

### Задача L02: Назначать из начальных/свободных денег без дохода

**Файлы:** Create `apps/api/src/envelope-plans/assignment.repository.ts`, `assignment.application.service.ts`, `assignment.schemas.ts`; Test `apps/api/test/v2-assignments.integration.test.ts`.

Period FK и budget/OWNER проверяются; `OPENING` разрешён только до первого подтверждённого дохода/расхода бюджета при начальной настройке; после этого свободные деньги помечаются `FREE` (миграционное OPENING создаёт отдельный операторский cutover M03).

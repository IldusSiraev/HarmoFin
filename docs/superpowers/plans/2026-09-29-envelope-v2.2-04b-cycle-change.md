# HarmoFin: план реализации Envelope Plan v2.2 — 04b. Изменение финансового цикла

> **Для исполнителя:** одна задача за сессию через субагентов, TDD, review, отчёт и стоп; без worktree. Читайте [индекс и порядок работы](2026-09-29-envelope-v2.2-00-roadmap.md), [спецификацию §9](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md) и только свой Task.

**Цель:** Позволить изменить начало/границу цикла в используемом бюджете, не переписывая подтверждённые назначения и даты операций.

**Архитектура:** Действовавшие настройки сохраняются по версиям с effectiveOn. Изменение вступает в силу с первой новой границы цикла, которая не пересекает подтверждённые прошлые периоды; возможный неполный переходный период показывается и подтверждается отдельно. Запросы истории читают записанные интервалы `EnvelopePeriod`, а не пересчитывают их из текущей настройки бюджета.

**Стек:** Node.js 24.20.0, pnpm 11.24.0, NestJS/Fastify, PostgreSQL 18, Nuxt 4/Vue 3, Vitest.

**Спецификация:** [v2.2](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md).

## Общие ограничения

- Доходы/расходы/переводы не меняют `occurredOn`; подтверждённые старые `EnvelopePeriod` и назначения не перезаписываются. Даты — календарные в timezone бюджета, не локаль браузера.
- Смена цикла требует явного подтверждения владельца и audit, подтверждённые суммы в переходе указывает владелец. V1 budget update не меняется; локально только unit/integration, Playwright — CI.

### Задача T02: Подтверждённая смена границ цикла без изменения истории

**Файлы:** Create `apps/api/src/cycles/cycle-revision.application.service.ts`, `cycle-revision.controller.ts`, `cycle-revision.dto.ts`, `cycle-revision.repository.ts`; Modify `apps/api/src/cycles/cycle.module.ts`, `apps/api/src/envelope-plans/period-target.application.service.ts`, `apps/api/src/obligations/mandatory-due.repository.ts`; Test `apps/api/test/v2-cycle-change.integration.test.ts`.

**Интерфейсы:** POST `/api/v2/budgets/:budgetId/cycle-change/preview` `{cycleStartDay,periodBoundaryOffset}` возвращает `{effectiveOn,transitionRanges,previewHash}`; POST `/api/v2/budgets/:budgetId/cycle-change/confirm` `{previewHash,transitionTargets:[{periodStart,target?:string|null}]}` с ключом идемпотентности создаёт `BudgetCycleRevision` и будущие интервалы. При первой смене сохраняется baseline revision на `planModelActivatedOn` со старыми настройками, затем новая revision с будущей датой вступления; `settingsAt(date)` выбирает последнюю подходящую запись либо старые поля Budget, если revision ещё нет. Существующие подтверждённые периоды и даты операций неизменны.

### Задача T02b: Остальные настройки бюджета и ограничение смены часового пояса

**Файлы:** Create `apps/api/src/cycles/v2-budget-settings.application.service.ts`, `v2-budget-settings.controller.ts`, `v2-budget-settings.dto.ts`, `v2-budget-settings.schemas.ts`; Modify `apps/api/src/cycles/cycle.module.ts`, `apps/api/src/envelope-plans/reset-unconfirmed-periods.ts`; Test `apps/api/test/v2-budget-settings.integration.test.ts`.

**Интерфейсы:** PATCH `/api/v2/budgets/:budgetId/settings` `{name?,allowNegativeAccountBalance?,timezone?}` меняет имя/политику **счёта**, не политику отрицательного виртуального конверта. `timezone` меняется только без подтверждённых операций, назначений, движений и CONFIRMED целей; системные UNSET/DRAFT периоды без ссылок безопасно перестраиваются под новую зону. Иначе `409 TIMEZONE_CHANGE_REQUIRES_RECONCILIATION`, поскольку в существующих фактах хранятся календарные даты, а не UTC-инстанты.

Имя меняется без перепланирования; отрицательный остаток конверта не блокируется флагом `allowNegativeAccountBalance`.

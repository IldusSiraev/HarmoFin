# HarmoFin: план реализации Envelope Plan v2.2 — 05. Дашборд, отчёты, экспорт, уведомления

> **Для исполнителя:** одна задача за сессию через субагентов, TDD, review, отчёт и стоп; без worktree. Читайте [индекс и порядок работы](2026-09-29-envelope-v2.2-00-roadmap.md), [спецификацию §8, §11–14](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md) и только свой Task.

**Цель:** Показать безопасный предел расходов, честные деньги/назначения и согласованные отчёты без v1 «физического конверта».

**Архитектура:** Репозитории читают account cash, виртуальные balances и обязательства из БД под бюджетным фильтром; application services применяют F05 формулы. Отчёты используют v2 ledger для целей/переносов, но исторические v1 физические операции показываются в денежных отчётах. Worker бюджета2 не исполняет старые правила дефицита v1.

**Стек:** Node.js 24.20.0, pnpm 11.24.0, NestJS/Fastify, PostgreSQL 18/Prisma, Vitest.

**Спецификация:** [v2.2](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md).

## Общие ограничения

- BigInt/minor units, только CONFIRMED, budget/workspace/role в server query. Учитывать просроченные, текущий и ближайший следующий период; будущие доходы не считать деньгами.
- V1 reports/dashboard остаются прежними для бюджета1; web бюджета2 читает только v2 проекции. Тесты на disposable DB; локально Playwright не запускать.

- `apps/api/src/reports/report-v2.repository.ts`, `report-v2.application.service.ts`, `report-v2.controller.ts`, `report-v2.dto.ts` — цели/план-факт и старые реальные операции без старого остатка.

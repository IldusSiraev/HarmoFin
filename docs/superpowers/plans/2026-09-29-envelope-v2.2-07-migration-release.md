# HarmoFin: план реализации Envelope Plan v2.2 — 07. Разовая миграция и выпуск

> **Для исполнителя:** одна задача за сессию через субагентов, TDD, review, отчёт и стоп; без worktree. Читайте [индекс и порядок работы](2026-09-29-envelope-v2.2-00-roadmap.md), [спецификацию §12–15](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md) и только свой Task. Production-операции НЕ выполнять без отдельного явного разрешения владельца.

**Цель:** Переключить действующий бюджет на v2.2 без движения денег, с восстановимой копией, ручным подтверждением неоднозначных назначений и E2E в CI.

**Архитектура:** Prisma schema-миграции уже совместимы с v1. Отдельный инструмент делает read-only preflight, затем dry-run; owner утверждает конкретные виртуальные opening assignments, при maintenance повторно проверяются snapshot и account balances, а переключение версии и assignments проходит в одной транзакции. Deploy tooling остаётся недеструктивным.

**Стек:** Node.js 24.20.0, pnpm 11.24.0, PostgreSQL 18/PITR, Prisma, Bash Docker Compose, Vitest, Playwright в CI.

**Спецификация:** [v2.2](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md).

## Общие ограничения

- Это разовая миграция одного бюджета, **не** универсальный пользовательский мастер. 681 134,70 ₽ и 139 738,76 ₽ — исторические наблюдения, не константы в коде/ожидаемый новый `free_to_assign`.
- Реальные `Transaction`, `Transfer`, `TransferPart` не изменять и не создавать; старые allocations/reallocations остаются историей. Opening assignment — только после согласования owner. Не выводить production payload в логи/CI.
- Production: backup+проверенный restore, остановлены v1 writers/worker, staged rehearsal, явный owner go/no-go. Без автоматического rollback БД; после новых v2 записей откат старого образа небезопасен.
- Интеграции только disposable DB; Playwright только CI, не локально.

## Карта файлов

- `apps/api/src/migrations/envelope-v2/preflight.ts`, `migration-preview.ts`, `cutover.ts`, `cli.ts` — изолированный одноразовый инструмент, не обычный API endpoint для будущих пользователей.
- `apps/api/test/v2-cutover.integration.test.ts`, `v2-cutover-failure.integration.test.ts` — снимки счетов, повтор, отказ при stale/неоднозначностях.
- `apps/api/src/auth/auth.application.service.ts`, `apps/api/src/budgets/budget.repository.ts`, Prisma migration позднего default — новые бюджеты2 **только после** готового web.
- `docs/runbooks/envelope-v2-cutover.md`, `infra/scripts/deploy.sh`, `infra/scripts/smoke.sh`, их tests — безопасная операторская процедура.
- `e2e/envelope-v2-onboarding.spec.ts`, `envelope-v2-payments.spec.ts`, `envelope-v2-period.spec.ts` — CI-only critical journeys.

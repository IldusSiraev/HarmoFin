# HarmoFin: план реализации Envelope Plan v2.2 — 08. Очистка после перехода

> **Для исполнителя:** одна задача за сессию, TDD, отчёт и стоп; без субагентов/worktree. Читайте [индекс](2026-09-29-envelope-v2.2-00-roadmap.md), [спецификацию §12 «Удаление неиспользуемого кода»](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md) и только свой Task. Деструктивные SQL-команды и удаление истории запрещены.

**Цель:** Убрать реально неиспользуемые v1 UI/API/worker-пути после завершения перехода, сохранив исторические операции, экспорт, аудит и балансы счетов.

**Архитектура:** Сначала доказать отсутствие бюджетов1 и активных v1 writers, затем мигрировать оставшихся читателей истории, только после этого удалять dead code. Legacy DB-таблицы и `transfer_parts` остаются read-only, пока не появится отдельная безопасная contract migration с backup; этот этап НЕ содержит DROP.

**Стек:** Node.js 24.20.0, pnpm 11.24.0, TypeScript, Prisma/PostgreSQL 18, Vitest, OpenAPI, Playwright в CI.

**Спецификация:** [v2.2](../specs/2026-09-29%20HarmoFin_Envelope_Plan_Model_v2.2.md).

## Общие ограничения

- Выполнение только после фактического успешного cutover (GATE: нет бюджета1 и неподдерживаемых клиентов v1). Если gate не пройден, STOP; не удалять ещё используемый код.
- Не удалять financial rows, audit events, `transfer_parts` из accountBalance, legacy schema без отдельного утверждённого contract-этапа и backup/restore. Не путать отсутствие вызовов web с отсутствием потребителей API.
- Малые независимые commits после тестов; локально Playwright не запускать, CI только с согласия владельца.

## Карта файлов

- `apps/api/src/transactions/`, `transfers/`, `allocations/`, `envelope-reallocations/`, `envelopes/`, `dashboard/`, `reports/`, `exports/`, `apps/api/src/app.module.ts` — убирать только неподдерживаемые контроллеры/сервисы; `FinancialBalanceRepository.accountBalance` с legacy history сохраняется.
- `apps/web/app/components/{transfers,operations,dashboard,envelopes}/`, `apps/web/app/composables/{useTransferForm,useBudgetReferenceData}.ts` — убрать лишь старые модельно-зависимые UI-пути.
- `apps/worker/src/{notification,plan-occurrence}.handler.ts`, `prisma/schema.prisma` — выключить старые ветки логики, схему оставить совместимой.
- `apps/api/test/`, `apps/web/app/**/*.test.ts`, `e2e/`, `docs/runbooks/envelope-v2-cutover.md` — сохранить проверки исторических данных и зафиксировать причины оставшегося legacy.

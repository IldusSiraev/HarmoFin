## Что изменилось в v2 (важно)

- Браузер НЕ считает деньги. Раньше суммы по дням (day-aggregates.ts) и плитки (plan-kpi.ts) считались в браузере BigInt-суммированием. Сейчас по правилам проекта (CLAUDE.md, «Financial correctness») суммы по дням, плитки и баланс должен отдавать сервер строками minor units. Значит, нужно новое ЧТЕНИЕ в API (additive, /api/v2): например GET /api/v2/budgets/:budgetId/plans/calendar?from=YYYY-MM-DD&to=YYYY-MM-DD, возвращающий по дням фактические доходы/расходы (только CONFIRMED, не удалённые), плановые возникновения платежей и доходов с статусами, а также итоги для плиток. Форму ответа, OpenAPI, фильтр по budget_id в самом запросе, роли и изоляцию бюджетов спроектируй в дизайне.
- Факты берутся из журнала операций v2 (GET transactions уже есть); плановые платежи и доходы — occurrences (GET obligations/occurrences, GET income-plans/occurrences). Только CONFIRMED операции влияют на суммы; плановое не равно фактическому; ожидаемый доход не входит в «На счетах» (спецификация §6, §8).
- У обязательного платежа в v2 нет счёта и конверта в плане: оплата идёт кнопкой «Оплатить» (создаёт расход из конверта «Обязательные», счёт и категория выбираются при оплате). Плана-«накопления» как типа в API нет (накопление — правило пополнения конверта, спецификация §7.3). В календаре и панели дня надо показывать, что есть в v2, не придумывая типов.
- Форма «Создать план» делается в ОТДЕЛЬНОЙ задаче другой сессии (кнопка «Добавить платёж», панель с полями название/сумма/дата/повторение/категория). Календарь должен переиспользовать эту форму, когда она появится (кнопка «Добавить план» в панели дня подставляет дату). Если формы ещё нет в ветке, спроектируй точку интеграции (событие/слот) и не делай вторую форму.

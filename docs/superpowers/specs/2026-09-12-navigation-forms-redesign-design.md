# Дизайн: редизайн навигации, форм и UX-плотности приложения

**Версия:** 1.0
**Дата:** 12.09.2026
**Статус:** черновик для согласования

## Контекст

После Stage 8 (PR #15) визуальный язык HarmoFin (палитра teal/navy, типографика Inter, карточки) устоялся, но пользовательский обзор выявил ряд проблем в навигации и UX-плотности:

1. Часть страниц раздела `/app` не задавала `layout: 'app'` в `definePageMeta`, а четыре страницы (`accounts`, `envelopes`, `categories`, `settings`) хранили собственный старый `<header>` с обрезанным набором ссылок (Настройки/Главная) поверх общего `AppHeader`. Это уже исправлено отдельным багфиксом и в объём данного документа не входит.
2. Основная навигация — плоский список из 7 пунктов в горизонтальном топ-меню, при этом раздел «Переводы» вообще не входит в меню (доступен только по ссылке со страницы счёта).
3. Формы создания/редактирования (счета, конверты, категории, планы, переводы, операции) открываются инлайново над списком данных, раздвигая страницу, — кроме `AddOperationModal`/`AddTransferModal` на дашборде, которые уже используют модальное окно (`UiModal`).
4. Фильтры на страницах «Операции» и «Аналитика» показывают 6–8 полей одновременно, из-за чего данные уходят на второй экран.
5. Отступы между блоками страницы плывут: например, на «Счета» select «Показать счета» визуально прилипает к блоку empty state — общего вертикального ритма между заголовком, тулбаром и контентом нет, каждая reference-страница копирует свою разметку и CSS независимо.
6. Высота контролов (`--hf-control-height-md` = 3rem/48px) одинакова для десктопа и мобилки — на десктопе ощущается тяжеловесно.
7. Нет способа дать пользователю короткую подсказку о смысле поля/кнопки, не загромождая форму постоянным текстом.

## Цели

- Модернизировать навигацию: все разделы (включая «Переводы») доступны из одного места, список не выглядит перегруженным.
- Все формы создания/редактирования (кроме страниц, которые сами по себе являются формой — «Настройки») открываются в модальном окне.
- Панели фильтров компактны по умолчанию, не конкурируют с данными за место на экране.
- Единый вертикальный ритм отступов между блоками страницы через общий layout-компонент вместо копипасты разметки.
- Точечные подсказки (tooltip) по иконке рядом с полем/кнопкой, показываются только если подсказка задана.
- Контролы компактнее на десктопе, с сохранением touch-target 44px там, где действительно нужен сенсорный ввод (мобилка, мобильное меню).

## Не-цели

- Не меняем цветовую палитру и типографику Stage 8 (teal/navy/Inter остаются).
- Не трогаем бизнес-логику, API-контракты, финансовые расчёты.
- Не переделываем страницу «Настройки» в модалку — это самостоятельная страница-форма.
- Не добавляем новые разделы/функциональность сверх MVP.

## Навигация: переход на боковое меню

Горизонтальный топ-nav заменяется на левый сайдбар (десктоп ≥1024px), с сохранением текущего slide-in меню на мобилке/планшете.

Причина: приложения для учёта бюджета по конвертам (YNAB, Monarch, Copilot) используют боковую навигацию — это сигнализирует «инструмент», а не «сайт», и легко масштабируется на будущие разделы без перегрузки одной строки.

Структура пунктов сайдбара:

```
HarmoFin (wordmark, ссылка на /app)
─────────────────
Главная
─────────────────
Учёт
  Операции
  Переводы
  Планы
─────────────────
Справочники
  Счета
  Конверты
  Категории
─────────────────
Аналитика
Уведомления
─────────────────
(низ сайдбара, прижат вниз)
Настройки
[email] · Выйти
```

«Переводы» добавляется в постоянную навигацию (сейчас отсутствует). Секции «Учёт» и «Справочники» — статический некликабельный заголовок-разделитель (не аккордеон, не сворачиваются — весь список помещается на экран, скрывать нечего).

Разбивка по брейкпоинтам, без задвоения элементов:

- **Десктоп (≥1024px)**: `AppHeader` не показывается. `AppSidebar` — единственная навигационная поверхность: wordmark сверху, ссылки разделов, внизу — user-блок (email, ссылка «Настройки», кнопка «Выйти») вместо выпадающего `AppUserMenu`.
- **Мобилка/планшет (<1024px)**: как сейчас — `AppHeader` (hamburger + wordmark + `AppUserMenu`-дропдаун), `AppSidebar` скрыт, вход через `AppMobileMenu`.

Компонентные изменения:

```
apps/web/app/components/app/
├── AppSidebar.vue          # новый: десктопная навигация ≥1024px, включает user-блок внизу
├── AppSidebarSection.vue   # новый: группа-заголовок + ссылки
├── AppMobileMenu.vue       # без изменений в структуре ссылок, добавить «Переводы»
├── AppHeader.vue           # остаётся только для <1024px: mobile-button + wordmark + AppUserMenu
└── AppNavigation.vue       # удаляется, заменён AppSidebar (десктоп) и существующим AppMobileMenu (мобилка)
```

`app.vue` layout: на десктопе — `grid` из двух колонок (`AppSidebar` + контент, `AppHeader` не рендерится); на мобилке/планшете — одна колонка с `AppHeader` сверху, как сейчас.

## Формы: миграция на модальные окна

Правило: любая форма создания/редактирования сущности открывается в `UiModal`, за исключением страниц, которые сами по себе являются формой (Настройки бюджета).

Затронутые страницы и их текущий inline-паттерн (класс `reference-form`, локальный `ref` `formOpen`/`editingId`):

| Страница | Форма | Новый компонент |
|---|---|---|
| `accounts.vue` | создание/редактирование счёта | `AccountFormModal.vue` |
| `envelopes.vue` | создание/редактирование конверта | `EnvelopeFormModal.vue` |
| `categories.vue` | создание/редактирование категории | `CategoryFormModal.vue` |
| `plans.vue` | создание/редактирование плана | `PlanFormModal.vue` |
| `transfers.vue` | создание перевода | `TransferFormModal.vue` (переиспользует markup `AddTransferModal`) |
| `operations.vue` | создание/редактирование операции, распределение дохода | `OperationFormModal.vue` (переиспользует markup `AddOperationModal`) |

Каждый `*FormModal.vue` — тонкая обёртка: `UiModal` + существующий набор полей формы, без изменения бизнес-логики/composables (`useReferenceDataForm`, `useOperationForm` и т.д. остаются как есть). Меняется только способ показа — вместо `v-if="formOpen"` внутри страницы, модалка монтируется через `UiModal :open="formOpen"`.

Кнопки, открывающие форму («Создать счёт», «Новый перевод» и т.д.), остаются на месте (шапка страницы/панель действий).

## Фильтры: компактная панель

Текущее поведение (Операции, Аналитика): все поля фильтра отображаются одновременно в grid-раскладке над списком.

Новое поведение:
- Всегда видна одна строка: поле поиска (где применимо) + 1–2 самых частых фильтра (например, «Тип» и «Статус» для операций) + кнопка «Фильтры» со счётчиком активных фильтров.
- Остальные поля (даты, счёт, категория, конверт, план, сортировка) переезжают в выпадающую панель (popover якорем к кнопке «Фильтры» на десктопе, полноэкранная панель на мобилке — переиспользуем `UiModal` в полноэкранном мобильном режиме, который уже есть).
- Активные фильтры из скрытой панели отображаются как чипы под строкой поиска с крестиком для быстрого сброса по одному.

Новый компонент: `FilterPanel.vue` (`apps/web/app/components/ui/FilterPanel.vue`) — принимает slot с полями, управляет open/closed состоянием и позиционированием (popover/полноэкранная панель по брейкпоинту).

## Тултипы по иконке

Новый компонент `UiTooltip.vue` (`apps/web/app/components/ui/Tooltip.vue`): доступная обёртка, показ по hover И focus, закрытие по Escape, привязка через `aria-describedby`. Обычный `title` не используется — не работает с touch и слабо доступен для screen reader.

Использование:
- `UiInput`/`UiSelect` получают новый опциональный проп `tooltip` (отдельно от существующего `hint`, который остаётся видимым текстом-подсказкой по формату, например «Например, Europe/Moscow»). Если `tooltip` задан — рядом с `<label>` рендерится маленькая info-иконка (кнопка), при наведении/фокусе на которую показывается `UiTooltip` с текстом. Если `tooltip` не задан — иконки нет вообще.
- `UiButton` получает аналогичный опциональный проп `tooltip` для icon-only кнопок (например, действия в списках), с той же логикой.

## Единый ритм отступов: `ReferencePageLayout`

Вместо того чтобы каждая reference-страница (`accounts`, `envelopes`, `categories`, `plans`, `transfers`, `operations`, `analytics`) копировала разметку заголовка (`kicker` + `h1` + описание + действия) и свой набор CSS-классов с отступами, вводится общий layout-компонент:

```
apps/web/app/components/ui/ReferencePageLayout.vue
  slots: kicker, title, description, actions, filters, content
```

Фиксированный вертикальный ритм внутри компонента (не завязан на память каждой страницы задавать свои `margin-top`):
- kicker → title: `--hf-space-2`
- title/description → actions: `--hf-space-6`
- actions → filters: `--hf-space-6`
- filters → content: `--hf-space-5` (это и есть отступ, который сейчас отсутствует на «Счетах» между select и empty state)

Каждая reference-страница переходит на этот компонент, убирая свой локальный `.reference-page__*`/`.plans-page__*`/`...-page__*` CSS с дублирующимися правилами отступов.

## Плотность контролов: десктоп/тач

Текущие токены:
```
--hf-control-height-sm: 2.75rem  /* 44px */
--hf-control-height-md: 3rem     /* 48px */
--hf-control-height-lg: 3.25rem  /* 52px */
```

Вводится десктопное переопределение через media query (не меняем сами токены, чтобы не ломать мобильную доступность):

```css
@media (min-width: 1024px) {
  :root {
    --hf-control-height-sm: 2.25rem; /* 36px */
    --hf-control-height-md: 2.5rem;  /* 40px */
    --hf-control-height-lg: 2.75rem; /* 44px */
  }
}
```

На мобилке/планшете (<1024px) высоты остаются как сейчас (44px+) — сохраняется touch-target требование. Кнопки, являющиеся единственным способом закрыть модалку/меню (`modal__close`, `mobile-menu__close`), сохраняют `min-width/min-height: 44px` инлайново независимо от токена (уже так и сделано).

## Изменения токенов (`tokens.css`)

```css
/* Тултипы */
--hf-z-index-tooltip: 150;
--hf-tooltip-background: var(--hf-color-brand-navy);
--hf-tooltip-color: var(--hf-color-white);

/* Сайдбар */
--hf-sidebar-width: 16rem;
--hf-sidebar-width-collapsed: 4.5rem; /* резерв на будущее, не используется в этой итерации */
```

Плюс десктопное переопределение `--hf-control-height-*` из раздела выше.

## Тестирование

Playwright (обновление существующих + новые сценарии):
- Сайдбар: все пункты (включая «Переводы») кликабельны, активный пункт подсвечен, мобильное меню открывается/закрывается как раньше.
- Формы: клик «Создать/Изменить» открывает `UiModal`, сохранение закрывает модалку и обновляет список, Escape/backdrop/крестик закрывают без сохранения.
- Фильтры: кнопка «Фильтры» открывает панель, применённый фильтр даёт чип, сброс чипа возвращает список к состоянию по умолчанию.
- Тултипы: иконка появляется только когда `tooltip` задан, показывается по hover и по focus (клавиатура), скрывается по Escape.

Vitest:
- `ReferencePageLayout` рендерит слоты в правильном порядке.
- `UiTooltip` не рендерит контент, если текст не передан; `aria-describedby` корректно связывает иконку и содержимое.
- `UiInput`/`UiSelect`/`UiButton`: снапшот с `tooltip` и без.

## Доступность

- Тултип: `aria-describedby`, доступен с клавиатуры (focus показывает так же, как hover), Escape закрывает, не блокирует табуляцию.
- Сайдбар: `<nav>` с `aria-label`, активный пункт — `aria-current="page"`.
- Панель фильтров: `role="dialog"`/`aria-expanded` на кнопке-триггере, фокус возвращается на кнопку при закрытии.
- Контраст и фокус-индикаторы не меняются относительно текущих токенов.

## Порядок реализации (для implementation-плана)

1. `ReferencePageLayout` + перевод всех reference-страниц на него (заодно решает проблему отступов).
2. Сайдбар (`AppSidebar`, изменение `app.vue`, `AppHeader`), добавление «Переводы» в навигацию.
3. `UiTooltip` + проп `tooltip` в `UiInput`/`UiSelect`/`UiButton`.
4. Модалки форм (`AccountFormModal` и т.д.) — по одной странице за раз.
5. `FilterPanel` + перевод фильтров «Операции»/«Аналитика».
6. Десктопные размеры контролов (media query в `tokens.css`).

Каждый пункт — независимая единица работы, можно проверять и коммитить по отдельности.

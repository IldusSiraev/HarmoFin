# HarmoFin Visual Guidelines — "Calm Fintech"

**Статус:** действующее направление, согласовано с пользователем 17.09.2026.
**Область:** `apps/web` presentation layer только — не меняет бизнес-правила, домен или API.
**Как появилось:** третья попытка визуального направления в рамках одной сессии; первые две были явно отклонены (см. «Что не делать» ниже). Не предлагать их снова без явного запроса пользователя.

Правки применялись пошагово на ветке `design/calm-fintech`; прогресс/чек-лист — в [2026-09-17-calm-fintech-ui-refresh.md](../plans/2026-09-17-calm-fintech-ui-refresh.md).

## Направление

Название: **Calm Fintech / Editorial Finance**. Не банковский кабинет с десятком KPI-карточек — один главный ответ («Можно потратить»), затем детали по запросу.

Источники, на которые опирались: собственный текстовый бриф пользователя с ASCII-макетами и hex-палитрой (`docs/chat_gpt/Предложения UI.md`), скриншот стороннего продукта «Budglee» (общая эстетика), Figma Make прототип пользователя (почти идентичная нашей IA структура страниц — подтвердил, что текущая навигация верна), скриншот категорий из проекта «FamFi» (конкретный референс для компактных icon-only действий в строках списка).

## Что не делать (отклонено пользователем)

- **Generic AI SaaS** — стандартная Tailwind-палитра slate-900/500/200/50 + синий #1d6fd6 + зелёный #0a7f60. Именно это пользователь назвал «несовременным» в самом начале.
- **«Ledger»** — тёплая бумажная палитра, serif-шрифт (PT Serif) для заголовков и суммы, «клапан конверта» как фирменный элемент. Отклонено целиком фразой «не нравится, хочется современный интерфейс» — не пытаться реанимировать отдельные части (шрифт, тёплые тона) без явного запроса.

## Палитра

Токены в [tokens.css](../../../apps/web/app/assets/styles/tokens.css) — не generic-палитра, а собственный набор HarmoFin: Navy `#0D1B2A` (текст/тёмная тема), Teal `#1BA39C` (primary/brand — единственный основной акцент для действий), Green `#22A06B` (только статус «успех»/положительные суммы), Blue `#2C5B8A` (только статус «инфо»), Mint `#73C6B6` (второй акцент для графиков). Фон — холодный светло-серый `#F7F9FA`, не кремовый/тёплый.

Принцип: **цвет — только для состояния**, не для декора. Расход не красится в красный по умолчанию (только явный статус «дефицит»/«в архиве» получает цвет). Не красить каждую сумму в дашборде в зелёный/красный светофором.

## Кнопки и действия — важно, была явная правка

Первая версия действий над строкой списка (категории) — две большие цветные кнопки на всю ширину («Изменить» — серый pill, «Переместить в архив» — красный pill). Пользователь прислал референс (FamFi) и явно попросил заменить на компактные **icon-only** кнопки без фона. Это теперь правило, а не разовая правка:

- Действия уровня строки/списка (edit, archive и т.п.) — **всегда компактные icon-only кнопки**, не текстовые pill-кнопки с фоном на всю ширину.
- Паттерн: `UiButton variant="tertiary" size="sm"` с иконкой вместо текста и **обязательным** `aria-label` (кнопка без видимого текста обязана иметь доступное имя). Пример — [categories.vue](../../../apps/web/app/pages/app/categories.vue).
- Полноразмерные `UiButton` с текстом остаются для **основных** действий страницы/формы (создать, сохранить, подтвердить) — не для действий внутри строки списка.
- Если действий на строку больше 3–4, использовать уже существующий `UiActionMenu` (кебаб-меню), как в журнале операций — не плодить длинный ряд иконок.
- Icon-only кнопки/меню рядом с верхним краем страницы (сайдбар, шапка) — тултип обязателен через `tooltip`/`tooltip-placement="bottom"` (`UiButton`/`UiActionMenu`), иначе он всплывает вверх и обрезается краем окна. По умолчанию тултип открывается вверх (`placement="top"`) — это годится только когда над элементом достаточно места.
- Всплывающее меню (`UiActionMenu`) рядом с левым краем — `align="start"` (открывается вправо), рядом с правым краем — `align="end"` (открывается влево, значение по умолчанию). Проверять вживую, что список не уезжает за границу окна.
- Если один и тот же компонент с popup/меню рендерится в нескольких местах одновременно (например, в сайдбаре и в шапке страницы) — id для `aria-controls` должен быть уникальным на странице (генерировать через `useId()`), а не захардкожен, иначе получится дублирующийся `id` в DOM.

## Иконки

- Библиотека — `@lucide/vue`, уже используется по всему проекту. Не подключать другую иконочную библиотеку.
- Для доменных иконок переиспользовать существующий mapping, а не изобретать новый на каждой странице: `categoryIcon()` из [category-icon.ts](../../../apps/web/app/components/operations/category-icon.ts) для категорий/операций, `ACCOUNT_TYPE_ICONS`/`accountSubtitle()` из [account-type.ts](../../../apps/web/app/components/accounts/account-type.ts) для счетов, `ENVELOPE_TYPE_ICONS`/`envelopeSubtitle()` из [envelope-type.ts](../../../apps/web/app/components/envelopes/envelope-type.ts) для конвертов.
- Списки счетов/конвертов (в том числе сводные виджеты дашборда) показывают маленькую icon-аватарку по типу записи — тот же приём, что и у дочерних категорий: `width/height: 2.25rem`, `border-radius: var(--hf-radius-md)`, `background: var(--hf-color-surface-subtle)`, `color: var(--hf-color-text-muted)`. Не красить аватарку в цвет по типу (это декоративная раскраска, а не статус) — см. правило «цвет только для состояния» выше.
- Иконка без подписи — всегда с `aria-hidden="true"` на самой иконке и `aria-label` на интерактивном родителе (кнопке/ссылке).
- Ссылка «показать всё» в конце списка/карточки (например, «Все счета», «Все операции») — не голый текст, а `UiMoreLink` ([MoreLink.vue](../../../apps/web/app/components/ui/MoreLink.vue)): текст + иконка стрелки, без подчёркивания в состоянии покоя. Не использовать обычный `NuxtLink` с текстом для этого случая.

## Списки и иерархия

- Если у данных есть иерархия (категории с `parentId`) — плоский список строк с отступом для потомков и маленькой icon-аватаркой у дочерних элементов, а не карточная сетка (`grid` из `<article>` карточек). Корневой уровень — без иконки, обычная строка.
- Если данных группируются по дате (операции) — уже реализованный паттерн «activity feed»: `OperationGroup`/`OperationRow`, заголовок-дата, карточный список строк — не таблица.
- Двухколоночная раскладка (например, Доходы/Расходы) — `grid-template-columns: 1fr` на мобильном, `repeat(2, minmax(0,1fr))` от `768px`.
- Плоская коллекция независимых сущностей без иерархии (Счета) — сетка карточек (`grid-template-columns: repeat(2, minmax(0,1fr))` от `640px`), а не список строк. Карточка: иконка по типу + название + подпись сверху, крупная сумма справа, статус-пилюля и `UiMoreLink`-стиль «Подробнее →» снизу; вся карточка целиком кликабельна (открывает drawer с детальными действиями — изменить/архивировать/перевести), отдельного кебаб-меню на карточке не нужно, если у drawer уже есть те же действия в футере. Референс — Figma Make прототип пользователя, страница «Счета». Это не противоречит правилу про иерархические списки категорий выше: там карточки были отклонены из-за больших цветных кнопок-пилюль поверх строки, здесь карточка — это сама строка, без декоративной заливки под действия.

## Карточки и поверхности

Любой самостоятельный блок контента на странице (не строка внутри списка) — с полным card-оформлением из токенов: `border: 1px solid var(--hf-color-border); border-radius: var(--hf-radius-lg); background: var(--hf-color-surface); box-shadow: var(--hf-shadow-sm);`. Не оставлять блок «голым» на фоне страницы без поверхности — так уже было с таймлайном финансового месяца до явной правки пользователя.

## Типографика

Только Inter, без serif/display-шрифта — эту идею уже предлагали и отклонили («Ledger»). Крупная сумма («Можно потратить») — тот же Inter, просто большой кегль (`--hf-font-size-display`) и `font-variant-numeric: tabular-nums`.

## Прогрессивное раскрытие форм

Создание новой сущности с несколькими обязательными полями (операция) — пошаговая форма: один смысловой блок полей за раз, кнопки «Назад»/«Далее», «Далее» неактивна пока шаг не заполнен. Редактирование существующей записи — **всегда одним экраном** со всеми полями сразу: пошаговость помогает при вводе с нуля и мешает при точечной правке. См. [OperationForm.vue](../../../apps/web/app/components/operations/OperationForm.vue).

Это правило больше не действует для диалога быстрого добавления (кнопка «+»/«Добавить операцию» → «Что произошло?» → Расход/Доход/Перевод). Пользователь явно отменил пошаговость именно там 19.09.2026: расход/доход — самые частые операции в системе, и до-до-редактируемая пошаговая форма (`ШАГ 1 ИЗ 4`) была признана слишком медленной. Новый паттерн для этого диалога — **один экран без шагов**, реализован в [AppOperationEntryDialog.vue](../../../apps/web/app/components/app/AppOperationEntryDialog.vue):

- Общая шапка на все три типа — стрелка «назад» (к выбору типа), вкладки Расход/Доход/Перевод (переключение типа не закрывает диалог), крестик закрытия. Активная вкладка и крупная сумма красятся акцентным цветом типа: danger/success/info — это единственное место, где цвет кодирует тип, а не статус, потому что тип уже выбран пользователем как факт, а не как индикатор состояния записи.
- Сумма — крупный редактируемый инвертированный инпут (`OperationAmountField.vue`) с подчёркиванием и мини-степпером ±1 у.е., а не `UiInput`/`FinanceMoneyInput`.
- Счёт/Категория/Конверт — одиночный выбор компактными пилюлями (`UiPillSelect.vue`), а не `UiSelect`-дропдауны. Выбранная пилюля красится акцентом активного типа.
- Поля «Получатель» (расход) и «Источник дохода» (доход) объединены в одно поле «Заметка» в этом диалоге — доменная схема не менялась, это только переименование на уровне UI (`merchantName`/`sourceDescription` заполняются тем же полем в зависимости от типа).
- Единственная кнопка отправки — «Сохранить операцию», всегда подтверждает (`CONFIRMED`) сразу, без выбора «Черновик/Подтвердить». Черновики остаются доступны через полноценное редактирование существующей записи.
- Перевод в этом диалоге — всегда одна часть (конверт списания = конверт зачисления по умолчанию, как и в основной форме). Ссылка «Разбить перевод на несколько конвертов» передаёт уже заполненные поля в старую полную форму [TransferForm.vue](../../../apps/web/app/components/transfers/TransferForm.vue) для редкого случая разбивки по нескольким конвертам — не дублировать эту форму внутри быстрого диалога.

Другие формы создания/редактирования (журнал операций в режиме `edit`, счета, конверты, категории, планы) сохраняют текущие паттерны (пошаговость для создания, дропдауны, `UiSelect`) — не переносить пилюли/степпер туда без отдельного запроса и референса, по аналогии с тем, как «Ledger» не реанимируется частями.

## Светлая/тёмная тема

Реализовано через `[data-theme='dark']` в том же `tokens.css` (не отдельный файл/дублирование компонентов) и композабл [useColorScheme.ts](../../../apps/web/app/composables/useColorScheme.ts). Переключатель — компактная icon-only кнопка (Sun/Moon) в сайдбаре, не текстовая кнопка с подписью — по тому же правилу про действия.

Правила при добавлении новых токенов на будущее:

- Заливки кнопок/бренд-цвета (teal/green) обычно не нуждаются в отдельном значении для тёмной темы — они уже достаточно яркие на тёмном фоне.
- Цвета, используемые как **текст** (danger/info/warning), в тёмной теме почти всегда нужно осветлять — иначе контраст не пройдёт. Не полагаться на «то же значение сработает».
- Перед тем как считать тёмную тему готовой, проверять реальный `getComputedStyle(...).color` через браузер, а не только визуально — именно так был пойман баг, когда текст суммы получил тот же цвет, что и фон.

## Процесс (для будущих похожих задач)

- Не гадать с направлением после первого отказа — просить у пользователя конкретный референс (скриншот/ссылку) вместо повторного изобретения палитры с нуля.
- Каждый визуальный шаг — проверять вживую в браузере с реальными данными (не только unit-тестами) до того, как показывать результат.
- Крупную визуальную переделку — отдельной веткой, коммит на каждый согласованный шаг, чек-лист в `docs/superpowers/plans/`, чтобы не потерять прогресс между сессиями.

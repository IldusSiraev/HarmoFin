# Дизайн: редизайн страницы настроек (`/app/settings`)

**Версия:** 1.0
**Дата:** 19.09.2026
**Статус:** черновик для согласования

## Контекст

Текущая `/app/settings` ([settings.vue](../../../apps/web/app/pages/app/settings.vue)) — одна форма из 6 полей (название, часовой пояс, начало финансового месяца, граница периода, чекбокс «уходить в минус», чекбокс правила дохода) плюс отдельный блок «Базовый шаблон». Страница визуально не соответствует направлению Calm Fintech (нет карточного оформления, нет группировки по смыслу), использует специфичные термины без объяснения для части полей, и не даёт доступа к уже существующим в backend, но не выведенным в UI настроек возможностям — смене пароля, списку сессий.

Пользователь предоставил референс-скриншот стороннего продукта: страница настроек разбита на именованные карточки («Бюджет», «Аккаунт», «Данные», «Финансовый цикл»), внутри карточек — строки вида «подпись + значение/ссылка „Изменить →“», финансовый цикл — отдельный крупный блок с двумя полями и наглядным превью разбивки периода. Референсная карточка «Данные» (экспорт/бэкап/удаление аккаунта) в наш дизайн не переносится: экспорт операций в CSV уже реализован и доступен пользователю — кнопка в тулбаре [operations.vue:386-409](../../../apps/web/app/pages/app/operations.vue#L386-L409) (учитывает текущие фильтры журнала операций), дублировать его в настройках как «полный экспорт без фильтров» не нужно — два входа в один и тот же экспорт с разным поведением только запутают; бэкап/удаление аккаунта — вне объёма (см. «Не-цели»).

## Цели

- Перегруппировать существующие поля бюджета в карточки по смыслу, приблизив компоновку к референсу.
- Дать доступ из настроек к уже реализованному в backend, но не выведенному в UI настроек функционалу: смена пароля (`auth/password`), список и отзыв сессий (`auth/sessions`).
- Добавить тултипы ко всем не самоочевидным полям (часовой пояс, «уходить в минус», в дополнение к уже существующим у `cycleStartDay`/`periodBoundaryOffset`).
- Заменить свободный текстовый ввод часового пояса на поиск по списку.
- Сделать визуальный превью разбивки финансового цикла на периоды.
- Убрать из UI настроенное правило автоматического распределения дохода (сейчас неактуальная фича).

## Не-цели

- Не добавляем резервное копирование и удаление аккаунта — в backend этого нет; отдельная будущая задача, вне объёма.
- Не удаляем правило распределения дохода из backend (схема, `allocationProposal` в создании операции, `OperationDrawer`, спеки, тесты) — отдельная будущая задача (breaking-change в `/api/v1`, требует плана миграции по правилам CLAUDE.md). В этой задаче правило только убирается из UI страницы настроек.
- Не добавляем редактирование имени/email — в backend нет эндпоинта для этого (`auth.controller.ts` не содержит `PATCH /me` или аналога); профиль показываем только для чтения.
- Не меняем семантику/валидацию `periodBoundaryOffset` (остаётся «дней от начала первого периода») и не пытаемся представить его как абсолютный «день месяца» — при переменной длине месяца это даёт неверный пересчёт для случаев, когда второй период уходит в следующий месяц (например, старт 25-го числа + смещение 15 дней = 9-е число следующего месяца). Правильность важнее визуального сходства с референсом в этой детали.
- Не меняем палитру/типографику Calm Fintech, не трогаем бизнес-логику расчётов бюджета/циклов/балансов.
- Backend-изменений не требуется — все используемые эндпоинты уже существуют.

## Информационная архитектура страницы

`/app/settings` становится страницей-хабом: карточки со строками, часть строк ведут на отдельные под-страницы через «Изменить →», часть — самостоятельные мини-формы прямо в карточке.

Двухколоночная раскладка (`grid-template-columns: 1fr` на мобильном, `repeat(2, minmax(0,1fr))` от `768px` — по аналогии с существующим паттерном двухколоночных блоков Calm Fintech), каждая карточка — стандартное card-оформление (`border`, `--hf-radius-lg`, `--hf-color-surface`, `--hf-shadow-sm`).

**Левая колонка:**

```
Карточка «Бюджет»
├── Общие настройки           [Изменить →]  → /app/settings/general
└── Базовый шаблон            [Создать]     (действие на месте, не переход)

Карточка «Аккаунт»
├── Email                     (текст, без ссылки — редактирование недоступно)
├── Пароль                    [Изменить →]  → /app/settings/password
└── Сессии                    [Управлять →] → /app/settings/sessions
```

**Правая колонка:**

```
Карточка «Финансовый цикл» (крупная, форма прямо в карточке, свой «Сохранить»)
├── Начало первого периода (cycleStartDay)
├── Граница второго периода (periodBoundaryOffset)
├── Превью-бар (два сегмента с вычисленными датами)
└── [Сохранить]
```

`allowNegativeBalance` — в карточке «Общие настройки» (`/app/settings/general`), не здесь: так было согласовано при выборе группировки (общие + баланс отдельно от доход-правила, цикл — отдельный блок без баланса).

Карточка «Финансовый цикл» независима от карточки «Общие настройки» — раздельные формы, раздельные состояния сохранения/ошибок, как и было решено в обсуждении (не превращаем всю страницу в одну форму).

На мобильном (одна колонка) порядок карточек: «Бюджет», «Финансовый цикл», «Аккаунт» — финансовый цикл поднят выше как наиболее часто используемая настройка.

Правило распределения дохода (`incomeAllocationRuleEnabled`/`incomeAllocationSourceCategoryId`/`incomeAllocationTargetEnvelopeId`) — полностью убирается из этой страницы, никакой замены/заглушки. Поля формы `settings.vue`, связанный код `useReferenceDataForm`/`useBudgetReferenceData` со стороны страницы настроек, использующий эти три поля, удаляются вместе с редизайном; сам API-контракт, типы в `useBudgetReferenceData.ts` и весь код операций, зависящий от `allocationProposal`, не трогаем.

## Карточка «Финансовый цикл»

Оставляем текущую семантику полей без изменений:

- `cycleStartDay` (1–28) — «Начало первого периода», тултип как сейчас.
- `periodBoundaryOffset` (1–27) — переименовать label в «Граница второго периода (дней от начала цикла)», тултип как сейчас.

Превью-бар — новый компонент `CyclePreview.vue` (`apps/web/app/components/settings/CyclePreview.vue`): два сегмента шириной пропорционально длине периода в условном 28-дневном месяце (чисто визуально, не для точных расчётов), с подписями вида «10–25» / «25–10», где вторая граница — `cycleStartDay + periodBoundaryOffset`, отображается как обычное число дня без попытки нормализовать к календарному дню месяца при переходе через конец месяца (в этом крайнем случае просто показываем число >28, например «40», это тестовый край, не основной сценарий использования). Компонент чисто презентационный, принимает `cycleStartDay`/`periodBoundaryOffset` пропами, обновляется реактивно по вводу — не делает запросов.

Под превью — информационная плашка. Текст референса («не влияет на прошлые данные, пересчитает со следующего месяца») не соответствует реальному поведению системы: по функциональной спецификации при изменении дня начала цикла приложение пересчитывает принадлежность операций к циклам и периодам сразу, историческая дата операции не меняется (см. [functional spec](2026-08-30-family-budget-app-spec.md), «При изменении дня начала цикла приложение должно пересчитать принадлежность операций к циклам и периодам. Историческая дата операции не изменяется»). Плашка отражает реальное поведение: «Изменение цикла не меняет даты операций, но пересчитывает их принадлежность к периодам и циклам».

## Тултипы

`UiInput`/`UiSelect`/чекбокс получают `tooltip`:

| Поле | Текст (уточнить формулировку при реализации) |
|---|---|
| `cycleStartDay` | существующий текст без изменений |
| `periodBoundaryOffset` | существующий текст без изменений |
| `timezone` | «Часовой пояс используется для расчёта границ финансового месяца и определения „сегодня“ на дашборде, в отчётах и планах» |
| `allowNegativeBalance` | «Если выключено, HarmoFin не даст сохранить операцию, которая уведёт счёт или конверт в минус» (текст уже есть как статичная подсказка под чекбоксом — переносится в тултип, статичный текст под полем убирается) |

## Часовой пояс: текст → поиск

`UiInput type=text` заменяется на `UiSelect` с поиском. У текущего [Select.vue](../../../apps/web/app/components/ui/Select.vue) поиска нет — добавляется новый режим (`searchable` проп или аналог), фильтрующий список опций по вводу. Список опций — `Intl.supportedValuesOf('timeZone')`, значение — сам IANA-идентификатор. Валидация на backend не меняется (уже принимает произвольную строку через `timezoneSchema`).

## Под-страницы

Все — полноценные route-страницы с layout `app`, не модалки (правило из [navigation-forms-redesign](2026-09-12-navigation-forms-redesign-design.md): страница-форма не оборачивается в `UiModal`; это распространяется и на новые под-страницы настроек).

### `/app/settings/general`

Поля: `name`, `timezone` (см. выше), `allowNegativeBalance`. Использует существующий `PATCH /budgets/:id` через `useBudgetReferenceData`, без изменений API-контракта (просто больше не отправляет три поля правила дохода).

### `/app/settings/password`

Поля: текущий пароль, новый пароль, подтверждение нового пароля. Вызывает `POST auth/password` (`ChangePasswordRequest`). Успешная смена — обновляет сессию (эндпоинт уже возвращает новую сессию), показывает статус успеха.

### `/app/settings/sessions`

Список через `GET auth/sessions` (`SessionResponse[]`: `id`, `createdAt`, `lastSeenAt`, `idleExpiresAt`, `absoluteExpiresAt`, `userAgent`). `SessionResponse` не содержит признака «это текущая сессия» (cookie с session-токеном HttpOnly, на фронте недоступна) — без изменения backend пометить текущую сессию нельзя, поэтому список показывается без такой пометки: каждая строка — `userAgent` (или «Неизвестное устройство», если `null`), дата создания, последняя активность, кнопка отзыва. Кнопка отзыва по одной сессии — `DELETE auth/sessions/:sessionId`. Кнопка «Выйти отовсюду» — `DELETE auth/sessions`, с подтверждением (необратимое действие, разлогинивает все устройства, включая текущее — после вызова пользователь тоже будет разлогинен и перенаправлен на страницу входа).

## Базовый шаблон

Переносится без изменения поведения — строка в карточке «Бюджет» с описанием и кнопкой «Создать», вызывающей существующий `initializeTemplate`.

## Доступность

- Все info-иконки тултипов — `aria-describedby`, доступны с клавиатуры (см. существующий `UiTooltip`).
- Карточки — обычные `<section aria-labelledby>`, без изменений паттерна доступности относительно остальных страниц.
- «Выйти отовсюду» — подтверждение перед необратимым действием (разлогинивает текущее устройство).
- Часовой пояс как `UiSelect` с поиском — должен оставаться управляемым с клавиатуры (открытие, фильтрация, выбор стрелками, Enter).

Каждый пункт — независимая единица работы, проверяется и коммитится отдельно.

# Дизайн: редизайн страницы «Планы» (`/app/plans`)

**Версия:** 1.0
**Дата:** 24.09.2026
**Статус:** согласован в чате, готов к implementation plan

## Контекст

Текущая `/app/plans` ([plans.vue](../../../apps/web/app/pages/app/plans.vue)) — список из двух секций («Ближайшие платежи» и «Все планы»), каждый план/occurrence — отдельная карточка (`PlanCard.vue`, `PlanOccurrenceCard.vue`), без визуального обзора по датам.

Пользователь дал референс (скриншоты стороннего продукта) на новый UX: календарь-сетка с финансовой статистикой по дням, панель деталей выбранного дня, список планов с табами «Ближайшие»/«Все», форма плана с героическим полем суммы. Разрешено добавлять API при необходимости — по факту разбора не потребовалось: оба нужных эндпоинта (`GET .../transactions`, `GET .../plans/occurrences`) уже принимают `from`/`to` на бэке, фронтовая обёртка `useBudgetReferenceData.ts` просто не прокидывала эти параметры для occurrences.

Решения, принятые в обсуждении (см. чат):
- Иконка плана берётся из иконки выбранной категории (`categoryIcon()`), отдельного поля/пикера иконок у плана не добавляем.
- Чекбокс «выполнено» у occurrence в панели дня сразу дёргает существующий `POST .../complete` (без промежуточного экрана черновика).
- Одна кнопка ✕ = логическое удаление плана (`DELETE .../plans/:id`, как сейчас). Отдельного действия «Деактивировать» в списке/панели дня больше нет — переключатель `isActive` живёт внутри формы редактирования.

## Цели

- Календарная сетка 6×7 с дневной суммой подтверждённых операций и индикатором запланированных occurrences.
- Панель деталей дня: операции + occurrences выбранной даты, отметка выполнения, инлайн-редактирование/удаление плана, кнопка добавления плана на эту дату.
- Список планов справа с табами «Ближайшие» (occurrences, сортировка по дате) и «Все» (все `RegularPlan`, группировка).
- Форма плана: переключатель типа (Расход/Доход/Накопление), героическое поле суммы, упрощённые даты, повторение, счёт/категория/конверт, режим редактирования с удалением и переключателем активности.
- KPI-строка: плановые доходы/расходы/баланс текущего видимого месяца, количество активных планов.

## Не-цели

- Backend/API/OpenAPI без изменений — используем только существующие эндпоинты.
- Не добавляем период «еженедельно» — функциональная спецификация (раздел 13.3) фиксирует только один раз/ежемесячно/раз в несколько месяцев/ежегодно, в API такого значения нет.
- Не добавляем отдельное поле/пикер иконки плана — решение выше.
- Не меняем модель/валидацию `RegularPlan` (обязательность `envelopeId` для Расход/Накопление и его запрет для Дохода — как в текущей `plans.schemas.ts`).
- Не переносим на эту страницу редактирование/удаление уже подтверждённых операций — они показываются в панели дня только для контекста (read-only), редактирование операций остаётся на `/app/operations`.
- Не меняем палитру/типографику Calm Fintech.

## Данные и API

Ничего нового на бэке. Правки со стороны фронта:

- `useBudgetReferenceData.ts`: расширить сигнатуру `listPlanOccurrences` — добавить `from`/`to` в тип входа (строка 663–666), они уже прокидываются через `withQuery` в реализации (строка 935–940), просто не были объявлены в типе.
- Диапазон запроса для календаря = границы видимой сетки (первая и последняя из 42 ячеек), не строго календарный месяц — так дни соседних месяцев тоже получают данные.
- Один `Promise.all` на смену месяца/маунт: `listTransactions(budgetId, { from, to, status: 'CONFIRMED' })` + `listPlanOccurrences(budgetId, { from, to })` (без фильтра статуса — нужны все, чтобы отличать просроченные/выполненные/отменённые).
- KPI-строка и панель дня переиспользуют те же два массива, без дополнительных запросов.

## Логика ячейки календаря

- Сетка: понедельник первым (совпадает с `week-start=1` у `UiDatePicker`), 42 ячейки, дни соседних месяцев — приглушённым цветом.
- Сумма дня = знаковая сумма `amountMinor` подтверждённых операций (`INCOME` +, `EXPENSE` −) за эту дату; при 0 — не показываем.
- Компактный формат: `|value| < 1000` → полная сумма (`formatMinorUnits`); иначе округление до тысяч со знаком и кириллическим «к» (`+106к`, `−3к`) — не английским «k», по правилу CLAUDE.md писать UI-текст на русском.
- Точка под числом: `DUE`-occurrence с `scheduledOn` в прошлом → красная (просрочен); иначе есть `PENDING`/`DUE` occurrence на эту дату → teal. `COMPLETED`/`SKIPPED`/`CANCELLED` точку не рисуют.
- Сегодня — teal-кружок вокруг числа дня; выбранный день — рамка (второе не исключает первое).
- Легенда снизу: «● Доход · ● Расход · ● Планы».

## Панель дня

- Заголовок — выбранная дата, под ним сумма расхода/дохода дня (из того же массива операций).
- Список операций дня — read-only строки (иконка категории, название, сумма).
- Список occurrences дня: чекбокс → `completePlanOccurrence` сразу (optimistic не делаем — ждём ответ сервера, как в текущем `runConfirmation`); при наведении — ✏️ (открыть `PlanForm` в режиме редактирования соответствующего `RegularPlan`) и ✕ (подтверждение → `deleteRegularPlan`).
- Функциональная спецификация (раздел 13.5) требует для occurrence в статусе `PENDING`/`DUE` пять действий: создать операцию, изменить план, пропустить этот раз, отметить выполненным, отключить план. Мокап показывает только чекбокс+✏️+✕ — этого недостаточно, «создать операцию» (кнопка «Создать черновик» — так она называется в текущем UI, оставляем формулировку) и «пропустить» обязательны и в мокап не попали. Ряд действий строится так: чекбокс (complete) + всегда видимые ✏️ (edit) и ✕ (remove) как на мокапе, плюс третий элемент — `UiActionMenu` ([ActionMenu.vue](../../../apps/web/app/components/ui/ActionMenu.vue), уже используется в журнале операций) с пунктами «Создать черновик» и «Пропустить», показывается только если хотя бы один из двух применим (условия видимости как в текущем `PlanOccurrenceCard.vue`: «Создать черновик» скрыт для `planType==='SAVINGS'` и когда `transactionId` уже есть; «Пропустить» скрыт при уже существующем `transactionId`). Три всегда видимых контрола (✏️/✕/⋯) вместо чистого hover — так действия остаются доступны с тачскрина (сенсорные экраны не имеют hover, а CLAUDE.md требует touch-friendly controls). «Отключить план» доступен через переключатель `isActive` в форме редактирования (открывается тем же ✏️) — отдельного пункта меню для него нет, это и есть согласованное упрощение.
- Кнопка «+ Добавить план на этот день» — открывает `PlanForm` создания с `anchorOn=startOn=` выбранная дата.

## Список справа

- Таб «Ближайшие»: occurrences со статусом `PENDING`/`DUE`, сортировка по `scheduledOn` возрастанию, из уже загруженного для календаря диапазона плюс дозагрузка на более широкий горизонт, если видимый диапазон меньше (например, при первом заходе смотрим на конец месяца — нужно быть уверенным, что «ближайшие» не обрежутся границей сетки; берём отдельный `listPlanOccurrences(budgetId, { status: 'DUE' })`/`{status:'PENDING', from: сегодня}` без верхней границы `to`, вместо переиспользования диапазона календаря). Строка occurrence в этом табе показывает те же действия, что и в панели дня: чекбокс «выполнено», «Создать операцию», «Пропустить», ✏️/✕ (те же условия видимости — см. «Панель дня»).
- Таб «Все»: `listRegularPlans(budgetId, 'all')`, группировка по активности (активные/отключённые) как сейчас в целом по смыслу, но в одном списке с меньшим количеством отдельных карточек-действий (только ✏️/✕ при наведении, без отдельной кнопки «Отключить» — отключение переехало в форму редактирования).
- Оба таба используют общий компонент строки для своего типа данных: occurrence-строка (таб «Ближайшие», плюс переиспользуется в панели дня) и plan-строка (таб «Все») — у них разный набор действий (см. выше), поэтому это два маленьких переиспользуемых компонента (`PlanOccurrenceRow.vue`, `PlanRow.vue`), а не один общий.

## KPI-строка

- «Плановые доходы» / «Плановые расходы» — сумма `amountMinor` occurrences видимого месяца (не всей сетки 42 ячеек, а календарного месяца) по `planType`, статус ≠ `CANCELLED`.
- «Баланс» — доходы минус расходы (Накопление считается расходом для этого баланса, как отток из бюджета).
- «Всего планов» — количество активных `RegularPlan` (`listRegularPlans(budgetId, 'active').length`), не привязано к месяцу.

## Форма плана

- Переключатель Расход/Доход/Накопление (третий вариант — расширение мокапа, обязателен по функциональной спецификации 13.2).
- Герой-поле суммы: `FinanceMoneyInput`, крупный шрифт, цвет и подчёркивающая линия меняются с типом (зелёный доход/красный расход/тоже акцентный для накопления — teal, вторичный акцент по Calm Fintech).
- «Дата» — один видимый инпут, пишет в `anchorOn` и `startOn` одновременно (сохраняя инвариант `anchorOn === startOn` для `ONE_TIME` из `plans.schemas.ts`).
- «Повторение»: Один раз / Ежемесячно / Раз в несколько месяцев (+ поле интервала) / Ежегодно.
- Счёт (необязательно), Категория (обязательно, фильтр по типу плана), Конверт (обязательно для Расход/Накопление, скрыт для Дохода — как сейчас).
- «Дополнительно» (свёрнуто по умолчанию): отдельная опорная дата (если отличается от даты начала — только для periodic-планов), дата окончания, заметка.
- Режим редактирования: кнопка «Удалить» (с подтверждением) + переключатель «Активен» (`isActive`) + «Сохранить изменения».

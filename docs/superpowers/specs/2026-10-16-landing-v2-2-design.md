# Лендинг под модель v2.2 — дизайн

Дата: 2026-10-16. Область: `apps/web/app/pages/index.vue`, `apps/web/app/components/landing/**`, `apps/web/app/data/landing*.ts`, `e2e/landing.spec.ts`. API, БД, приложение `/app/**` и финансовые правила не меняются.

Заменяет содержательную часть [дизайна лендинга 2026-09-13](2026-09-13-landing-redesign-design.md); общий визуальный язык по-прежнему задают [Calm Fintech guidelines](2026-09-17-calm-fintech-visual-guidelines.md).

## 1. Проблема

- Лендинг описывает модель до Envelope Plan v2.2: конверт «Свободные», «Обязательные» вместо «Обязательные платежи», «назначение денег» в FAQ, нет «Не распределено», «Переложить», решения по остатку в конце периода.
- Лендинг показывает инфографику, которой нет в приложении: кольцевую диаграмму долей категорий (`DonutChart`), линейный график доходов и расходов за полгода (`CashFlowChart`), столбцы «план/факт» (`PlanVsFactBars`). Пользователь после регистрации их не найдёт.
- Ручные макеты (`components/landing/mockups/*`) расходятся с реальным интерфейсом при каждом изменении приложения.
- Тексты не следуют [глоссарию интерфейса](2026-10-16-ui-glossary-design.md).

## 2. Решение

1. Лендинг показывает только то, что есть в приложении. Визуалы — настоящие presentational-компоненты приложения с демо-данными, а не ручные макеты.
2. Все тексты — по глоссарию раздела 3 дизайна `ui-glossary`.
3. Секций становится 8 вместо 14.
4. Красивые графики аналитики — отдельная задача B (своя спецификация). Пока её нет, на лендинге нет графиков; после неё в секцию 7 добавятся её реальные виды.

### 2.1. Главная мысль

Деньги лежат на счетах, конверты показывают, на что они отложены. HarmoFin считает, сколько можно потратить сейчас, не задевая обязательные платежи и накопления.

Якоря: `#features` (секция 3), `#how-it-works` (секция 4), `#security`, `#faq` — навигация шапки и подвала не меняется.

### 3.1. FAQ

Остаются: «Что такое HarmoFin?», «Нужно ли получать одинаковую зарплату каждый месяц?», «Есть ли банковская синхронизация?» (нет, не в v1), «Можно ли пользоваться с телефона?». Добавляются: «Что значит „Можно потратить“?», «Что значит „Не распределено“?», «Что будет с остатком в конце периода?», «Можно ли копить на отдельные цели?» (конверты «Накопления»). Ответы — без слов «назначение» в смысле раскладывания денег, без «защищено», «горизонт».

## 4. Демо-витрины

### 4.1. `LandingShowcase`

Новый компонент `components/landing/ui/LandingShowcase.vue`:

```html
<figure class="landing-showcase">
  <div inert class="landing-showcase__frame"><slot /></div>
  <figcaption>{{ caption }}</figcaption>
</figure>
```

- `inert` отключает клики, фокус и вызовы API у реальных компонентов (например, кнопки `PeriodDecisionCard` отправляют мутации). Без сессии такой вызов дал бы 401 и ошибку в консоли.
- Внутренности витрины исключены из дерева доступности; смысл передаёт видимая `<figcaption>`.
- Рамка — карточка Calm Fintech; витрина не масштабируется трансформацией, а живёт в обычной вёрстке, чтобы светлая/тёмная тема и адаптивность работали как в приложении.

### 4.2. Демо-данные

Файл `data/landing-demo.ts` экспортирует объекты тех же типов, что и приложение (`DashboardV2Response`, `EnvelopePlanDto`, `GoalProgressRowDto`, `PlanVsActualRowDto` и т. п.). Суммы — строки minor units, согласованные вручную по формуле раздела 8 модели v2.2 (например, «Можно потратить» не больше остатка лимита на период и денег на счетах после отложенного). Лендинг ничего не считает. Расхождение с изменившимся API ловит `pnpm typecheck`.

Даты демо-бюджета — фиксированные строки, не «сегодня»: SSR и гидратация дают одинаковую разметку.

### 4.3. Ограничения бандла

На лендинг попадают только компоненты без `echarts`. Тест `pages/index.build-chunks.test.ts` сохраняется без изменений. `ReportChart` и `pages/app/analytics.vue` на лендинг не импортируются.

Если компонент из таблицы раздела 3 при реализации требует контекста приложения, которого на лендинге нет (layout `app`, `useAuth` при монтировании, обязательный `navigateTo`), исполнитель не вносит в него лендинговые ветки, а фиксирует это в отчёте и заменяет витрину текстом секции. Правки в компоненты приложения ради лендинга не входят в задачу.

## 5. Удаление

- Секции: `ConceptSection`, `AvailableToSpendSection`, `FinancialCycleSection`, `IncomeAllocationSection`, `GoalsSection`, `PlansSection`, `HowItWorksSection`, `AudienceSection`, `AnalyticsSection`.
- Весь каталог `components/landing/mockups/`.
- `components/landing/format-money.ts`, `LandingMetric`, `LandingProgress`, если после переработки не используются.
- Неиспользуемые экспорты `data/landing.ts`.
- Тесты удалённых компонентов.

## 6. SEO

`data/landing-seo.ts`: заголовок сохраняется; `description`/`ogDescription` переписываются по словарю — про конверты, обязательные платежи и сумму «Можно потратить». TODO про canonical и og:image остаётся.

## 7. Тесты

По решению владельца тесты лендинга минимальны:

- Удаляются тесты удалённых секций и mockups; старые тесты сохранённых секций обновляются только настолько, чтобы проходили, или удаляются, если проверяют лишь тексты.
- Один тест `data/landing.test.ts`: в текстах лендинга (`data/landing.ts`, `data/landing-seo.ts`) нет `назнач` в любом регистре (на лендинге слово не нужно даже в смысле «предназначение»), `Свободные`, `Обязательства`, `Периодн`, `Пользовательская` (не «Пользовательское соглашение»), `защищен`, `горизонт`.
- `e2e/landing.spec.ts`: обновить ожидаемый H1; CTA «Начать бесплатно»/«Войти», якорь `#security` и вопрос «Что такое HarmoFin?» сохраняются. Проверка отсутствия ошибок консоли в первом тесте остаётся и покрывает витрины. E2E выполняет CI.
- Проверки: `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm --filter @harmofin/web build` (чтобы chunk-тест реально выполнился).

## 8. Ревью

UI/UX review (Calm Fintech, a11y витрин и `figcaption`, обе темы, мобильная вёрстка), QA, final review. Мутаций, эндпоинтов, доступа к данным и миграций нет: financial, security, API и backend review не требуются.

## 9. Вне объёма

- Новая страница аналитики с графиками — задача B, отдельная спецификация.
- Скриншоты, og:image, страницы `/privacy`, `/terms`, `/contacts`.
- Изменения компонентов приложения ради лендинга.

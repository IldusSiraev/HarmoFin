# Редизайн раздела «Конверты» — дизайн

Дата: 2026-10-21. Статус: утверждён владельцем, ждёт плана реализации.

Источник: макет владельца из Figma Make («Дизайн из JPG прототипа», пять экранов: страница «Конверты», «Распределить деньги», детали конверта, «Переложить», «Правила пополнения»), адаптированный к правилам Calm Fintech и к логике Envelope Plan Model v2.2.

## Цель

Сделать раздел «Конверты» нагляднее: сводка денег и действия, требующие внимания, сразу на странице конвертов; карточки конвертов с цветом типа и прогрессом; единый визуальный язык для всех диалогов раздела. Добавить в Calm Fintech цвет для типов конвертов и заметные статусы — сейчас интерфейс почти целиком бирюзово-чёрный.

## Не входит

- Изменения API, расчётов, правил распределения и переноса.
- Изменения текстов глоссария (`2026-10-16-ui-glossary-design.md`), кроме новых строк этого дизайна.
- Главная страница (кроме того, что `PeriodDecisionCard` получает новое оформление и используется в двух местах).

## Отклонения от макета

| В макете | Делаем | Почему |
|---|---|---|
| «Переложить»: в предпросмотре источник и получатель — один и тот же конверт | Источника нет среди получателей; перенос «в себя» возможен только между периодами, как сейчас | Ошибка макета; правило API |
| «Правила пополнения»: нативные `<select>`, текстовые «Выше/Ниже» | `UiSelect`, icon-only кнопки ↑/↓ с `aria-label` и тултипом | Calm Fintech: icon-only действия в строке; единые поля |
| Подзаголовок «Назначайте деньги целям…» | «Распределяйте деньги по целям, не перемещая их между счетами.» | Глоссарий: «распределить», не «назначить» |
| Переключатель темы в шапке страницы | Не добавляем | Уже есть в боковой панели |
| Метки в произвольном оранжевом | Токены `--hf-color-status-warning*` | Только цвета палитры |

## 1. Цвета и общие элементы

### 1.1. Цвет типа конверта

Новые токены в `apps/web/app/assets/styles/tokens.css`, светлая и тёмная темы:

| Тип | Токен | Светлая: цвет / фон | Тёмная: цвет / фон |
|---|---|---|---|
| `CURRENT_EXPENSES` | `--hf-color-envelope-current` / `-soft` | `#1BA39C` / `#E3F5F3` (существующие brand / brand-soft) | `#4DC9C1` / `rgb(27 163 156 / 18%)` |
| `MANDATORY_EXPENSES` | `--hf-color-envelope-mandatory` / `-soft` | `#2C5B8A` / `#E8EEF3` (существующие primary-strong / primary-soft) | `#6FB1E6` / `rgb(111 177 230 / 16%)` |
| `SAVINGS_GOAL` | `--hf-color-envelope-savings` / `-soft` | `#7C5CC4` / `#EFEAFA` | `#B49CF0` / `rgb(124 92 196 / 22%)` |
| `RESERVE` | `--hf-color-envelope-reserve` / `-soft` | `#4F5BD5` / `#ECEEFB` | `#98A1F2` / `rgb(79 91 213 / 22%)` |
| `CUSTOM` | `--hf-color-envelope-custom` / `-soft` | `#5B6B78` / `#EEF1F4` | `#93A2B8` / `rgb(255 255 255 / 8%)` |

Требование: цвет как иконка/текст на своём `-soft` фоне и на `--hf-color-surface` — контраст не ниже 4.5:1 в обеих темах. Если значение из таблицы не проходит, его затемняют (светлая тема) или осветляют (тёмная) до прохождения; итоговые значения фиксируются в tokens.css и гайдлайнах.

Где применяется цвет типа: плашка иконки конверта (фон `-soft`, иконка цветом), заполнение полосы прогресса, иконка типа в строках «Распределить деньги» и «Правила пополнения». Суммы, названия и текст карточки цвет типа не получают.

Соответствие типа и иконки берётся из существующего `planIcon` (`components/envelopes/envelope-plan-kind.ts`).

### 1.2. Заметные статусы

Строки и метки, на которые пользователь должен обратить внимание, окрашиваются целиком (мягкий фон, граница цвета статуса, иконка и действие цвета статуса):

| Тон | Токены | Где |
|---|---|---|
| `warning` (янтарный) | `--hf-color-status-warning`, `--hf-color-warning-soft` | «Не хватает на обязательные», «Нужно пополнить на X», нехватка в «Распределить деньги» |
| `danger` (красный) | `--hf-color-danger-strong` / `--hf-color-text-danger`, `--hf-color-danger-soft` | «Перерасход X», нехватка реальных денег (`CASH_SHORTFALL`) |
| `info` (синий) | `--hf-color-primary-strong`, `--hf-color-primary-soft` | «Не распределено · X», остаток прошлого периода |
| `success` (зелёный) | существующие success-токены | «Конверт в порядке», «+» в истории |

Каждый статус дублируется текстом и иконкой; цвет не единственный носитель смысла.

### 1.3. Общие компоненты (`apps/web/app/components/ui/` и `components/envelopes/`)

- `EnvelopeTypeIcon` (`components/envelopes/`) — props `envelopeType: string`, `size?: 'sm' | 'md'`; плашка 40px (md) / 32px (sm), радиус `--hf-radius-md`, фон и цвет иконки по 1.1, иконка `aria-hidden`.
- `UiProgress` (существующий `ui/Progress.vue`) — новый необязательный prop `tone?: 'current' | 'mandatory' | 'savings' | 'reserve' | 'custom' | 'warning' | 'danger'`, по умолчанию текущий вид. Процент по-прежнему из двух серверных строк.
- `UiAttentionRow` (`ui/AttentionRow.vue`) — props `tone: 'info' | 'warning' | 'danger'`, `title: string`, `description?: string`, `actionLabel?: string`, `actionTo?: string`; emits `action`. Иконка по тону (`Info`, `AlertTriangle`, `AlertOctagon`), действие — ссылка/кнопка-текст со стрелкой `ArrowRight`.
- `UiAmountHero` (`ui/AmountHero.vue`) — props `label: string`, `amountMinor: string`, `note?: string`; слот `aside` справа (метка статуса). Мягкий фон `--hf-color-surface-subtle`, сумма через `FinanceMoney`, крупный размер `--hf-font-size-display` (или ближайший существующий токен заголовка).
- `UiBeforeAfter` (`ui/BeforeAfter.vue`) — props `rows: Array<{ label: string; beforeMinor: string; afterMinor: string }>`; строка «Название · было → стало», «стало» выделено полужирным. Значения «стало» приходят из расчёта формы (сумма минус/плюс введённая), а не из сервера: это предпросмотр, сервер проверяет при сохранении.

### 1.4. Гайдлайны

В `docs/superpowers/specs/2026-09-17-calm-fintech-visual-guidelines.md` добавить раздел «Цвет типов конвертов и заметные статусы»: таблицы 1.1 и 1.2, правило «цвет типа — только плашка иконки и прогресс; суммы не красим», правило «заметный статус = фон + граница + иконка + текст». Существующий принцип «цвет только для состояния» уточняется: тип конверта считается категорией состояния назначения.

## 2. Страница «Конверты» (`EnvelopesPlanView.vue`)

### 2.1. Шапка

- Надзаголовок: «Конверты · {даты текущего периода}» (из `dashboard.period`, формат «10–24 октября»); без данных — «Справочники», как сейчас.
- Заголовок «Конверты», описание «Распределяйте деньги по целям, не перемещая их между счетами.»
- Действия: «Задать правила» (secondary, иконка `Settings2`), «Создать конверт» (primary, иконка `Plus`).

### 2.2. Сводка

Данные — `useEnvelopePlanV2().getDashboard(budgetId)`, загружаются параллельно со списком; ошибка сводки не ломает список (сводка скрывается, показывается строка «Сводка недоступна» с «Повторить»).

Карточка из трёх зон (на ширине < 1024px — столбиком):
1. «Можно потратить» — `spendable.amountMinor` крупно; пояснение «Остаток текущего периода · до {period.end}». Если `spendable.state === 'NEEDS_PERIOD_SETUP'` — текст «Лимит на период не настроен» и ссылка «Настроить» (тот же путь, что на Главной).
2. «Отложено на обязательные и накопления» — `mandatoryBalanceMinor + otherProtectedMinor` **не складывается в браузере**: показываются две строки «Обязательные платежи» (`mandatoryBalanceMinor`) и «Накопления и другие» (`otherProtectedMinor`); «На счетах» — `cashMinor`.
3. Строки внимания (`UiAttentionRow`), каждая видна только при сумме > 0:
   - `info`: «Не распределено · {freeToAssignMinor}», описание «Доход ещё не разложен по конвертам», действие «Распределить» → открывает существующий поток распределения свободных денег (тот же, что «Распределить» на Главной).
   - `warning` (`level: ALERT`) или `info` (`level: INFO`): «Не хватает на обязательные · {mandatoryGapMinor}», описание из `warning.message` для `MANDATORY_GAP`, действие «Покрыть» → `actionPath` предупреждения.
   - `danger`: «Не хватает денег на счетах · {unbackedMinor}» при `CASH_SHORTFALL`, действие по `actionPath`.

### 2.3. Остаток прошлого периода и перерасход

`PeriodDecisionCard` (из `components/dashboard/`) рендерится под сводкой с теми же props, что на Главной (`warnings`, `protectedAssignments`, `periodId`, `suggestedTarget`, `hideTarget: true`). Оформление карточки меняется в самом компоненте (и на Главной тоже): `PERIOD_LEFTOVER` — тон `info`, `PERIOD_DEFICIT` — тон `danger`; иконка календаря в плашке; основное действие («В следующий период») — secondary-кнопка на белом фоне, остальные — текстовые кнопки цвета тона. Логика и тексты действий не меняются.

### 2.4. Список

- Заголовок «Все конверты» и счётчик «{N} активных»; справа поле поиска `UiInput` с иконкой `Search`, `hideLabel`, label «Найти конверт» — фильтрует по названию без учёта регистра в браузере. Пустой результат — «Ничего не найдено».
- Группы по типу (существующие `PLAN_GROUPS`) с заголовком группы и коротким пояснением (`planScopeNote`); для «На текущие траты» — ещё «Первая/Вторая половина периода · даты».
- Карточка конверта (`EnvelopePlanRow` переделывается, сохраняя `@select` и слот `actions`):
  - слева `EnvelopeTypeIcon`, название, пояснение (для периодного — «Лимит на {первую|вторую} половину периода», для накоплений с целью — «Цель {сумма}», иначе `planScopeNote`);
  - центр: подпись «Осталось», сумма крупно, ниже мелко «Отложено X · потрачено Y»;
  - справа прогресс (см. 2.5) с подписью и процентом, под ним метка статуса, если есть;
  - кебаб-меню (существующее), без изменений состава.
- Карточка целиком кликабельна (открывает детали), как сейчас; клавиатура — Enter/Space.

### 2.5. Прогресс и метки в карточке

| Тип | Полоса | Подпись | Метка |
|---|---|---|---|
| На текущие траты (текущий период) | потрачено / отложено текущего периода (`periods[current]`) | «Потрачено из отложенного» | `danger` «Перерасход X», если остаток < 0 |
| Обязательные платежи | `min(balance, due)` / `due` с дашборда — **процент считается из двух серверных строк в `UiProgress`**, без вычитаний в браузере: передаются `value = mandatoryBalanceMinor`, `max = mandatoryDueMinor` (UiProgress ограничивает 100%) | «Покрыто ближайших платежей» | `warning` «Нужно пополнить на {mandatoryGapMinor}», если > 0 |
| Накопления, Резерв, Свой с целью (`targetAmountMinor`) | остаток / цель | «Цель» | — |
| Без цели | полосы нет | — | — |
| Любой с остатком < 0 | — | — | `danger` «Перерасход X» |

### 2.6. Мобильная версия

Одна колонка; в карточке прогресс уходит под сумму; кнопки шапки переносятся (уже исправлено в `ReferencePageLayout`); сводка — три блока столбиком.

## 3. Детали конверта (`EnvelopePlanDialog.vue`)

- Заголовок диалога — название конверта, подзаголовок — пояснение из карточки.
- `UiAmountHero` «Осталось» + в `aside` метка статуса: `success` «Конверт в порядке» / `warning` «Нужно пополнить» / `danger` «Перерасход».
- Ниже на desktop две колонки (≥ 768px), на mobile одна:
  - слева `dl` параметров: Область действия, Половина периода, Отложено, Потрачено, Цель, Правило пополнения;
  - справа «История» (заголовок + «Распределения, переносы и расходы»): строка — иконка вида записи в мягкой плашке (`ArrowDownToLine` распределение, `ArrowLeftRight` перенос, `ShoppingCart` расход), название, дата, сумма со знаком «+»/«−» (знак берётся из вида записи); «+» — цвет success, «−» — обычный текст. Переключатель «Показать отменённые записи» — `role="switch"`.
- Футер: «Переложить» (primary, иконка `ArrowLeftRight`), «Изменить цель периода», «Изменить» (`Pencil`), «Операции конверта» (`Calendar`) — secondary; «Архивировать» (`Archive`) — tertiary.

## 4. «Переложить» (`EnvelopeMovePanel.vue`)

- Подзаголовок «Источник: {название}».
- `UiAmountHero` «Сейчас в конверте».
- Направление — сегментированный переключатель (существующий `UiButtonGroup` или radio-группа в его стиле): «В другой конверт» / «Из свободных сюда» / «В свободные».
- «Конверт-получатель» — пилюли быстрого выбора (до 5 конвертов, по порядку списка, **без источника**) и `UiSelect searchable` для остальных; выбранная пилюля подсвечена brand.
- Для периодных конвертов — выбор периода, как сейчас.
- «Сумма» — `FinanceMoneyInput` с подсказкой «Можно переложить до {доступно}».
- `UiBeforeAfter`: строки источника и получателя («Свободные деньги» для направлений со свободными); значения «стало» считаются из строки суммы через целочисленные минорные единицы (существующие хелперы `decimalToMinor`), при некорректной сумме предпросмотр скрыт.
- Футер: «Отмена», «Переложить» / «Перенести и архивировать». Режим архивации не меняется по логике.

## 5. «Распределить деньги» (`FundingReviewSheet.vue`)

- Подзаголовок «{Источник} · {категория} · {дата}» (из имеющихся данных preview).
- `UiAmountHero` «Можно распределить», в `aside` — метка `info` «Деньги остаются на ваших счетах».
- Таблица-очередь: шапка «Очередь» / «Предложенная сумма»; строка — номер, `EnvelopeTypeIcon` (sm), название, причина предложения (существующий текст причины строки preview), поле суммы `FinanceMoneyInput` с `hideLabel` (label «Сумма для {название}»). Под строкой с фокусом — кнопки-пилюли «До нужной суммы» и «Весь остаток» (существующие действия).
- `UiAttentionRow` `warning` «Не хватает на обязательные платежи: X» с описанием «Можно распределить доступную сумму сейчас и покрыть нехватку позже» — когда preview сообщает нехватку.
- Закреплённый футер: «Распределено X · Осталось распределить Y» (значения как сейчас), «Позже» (secondary), «Распределить как предложено» (primary).
- Расчёты, idempotency и сценарии подтверждения не меняются.

## 6. «Правила пополнения» (`FundingRulesEditor.vue`, `FundingRuleCard.vue`)

- Каждая секция — `UiCard` с заголовком: плашка-иконка (`ArrowDownToLine` предложение, `ListOrdered` очередь, `Wallet` вне очереди), заголовок, подзаголовок-пояснение (тексты существующих подсказок), подсказка ⓘ остаётся.
- Предложение для дохода: переключатель справа в заголовке секции, ниже два `UiSelect` в строку.
- Карточка очереди на desktop (≥ 1024px) — одна строка: ручка, номер в тёмном кружке (`--hf-color-navy`, белый текст; в тёмной теме — светлый кружок), `EnvelopeTypeIcon` (sm), название (+ метка «Доход: …»), `UiSelect` типа, поле суммы/процента, icon-only ↑/↓. На меньшей ширине — текущая вертикальная раскладка.
- Между карточками — стрелка ↓ (как сейчас).
- «Вне очереди» — карточки с пунктирной границей в две колонки (≥ 768px), внутри — `EnvelopeTypeIcon`, название, текущий тип, `UiSelect` типа.
- Нижняя панель: слева статус — «Все изменения сохранены» (иконка `CircleCheck`, success) или «Есть несохранённые изменения» (`warning`), справа «Отменить изменения» и «Сохранить».

## 7. Доступность

- Все новые интерактивные элементы — клавиатура, видимый фокус, касание ≥ 44px.
- Статусы — текст + иконка; цвет не единственный носитель смысла.
- `UiAttentionRow` — `role="status"` не нужен (это не живое обновление); действие — настоящая ссылка/кнопка с текстом.
- Поиск по конвертам — `aria-label` через скрытую подпись; результат фильтрации объявляется в `aria-live="polite"` («Найдено N конвертов»).

## 8. Тестирование

- Unit (Vitest): `EnvelopeTypeIcon` (иконка и токены по типу), `UiProgress` tone, `UiAttentionRow` (тон, видимость, действие), `UiAmountHero`, `UiBeforeAfter`; страница: сводка показывает серверные значения и скрывает нулевые строки, ошибка сводки не ломает список, поиск фильтрует, прогресс и метки по таблице 2.5; детали: метка статуса и знаки истории; «Переложить»: источник не среди пилюль, предпросмотр «было → стало»; правила: статус нижней панели. Существующие тесты обновляются под новую разметку без потери проверок поведения.
- E2E (CI): обновить селекторы затронутых сценариев (`envelope-v2-*.spec.ts`, `envelope-v2-funding-rules.spec.ts`, `reference-data.spec.ts`), сохранить проверку отсутствия горизонтальной прокрутки на 375px; локально не запускать без запроса владельца.
- Ревью: UI/UX, QA, финальное. API и финансовой логики изменения не касаются; финансовое ревью не требуется, если план не затронет расчёты.

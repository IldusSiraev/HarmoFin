# Лента «что сделали другие с прошлого визита» — дизайн

Дата: 30.10.2026. Статус: согласован владельцем. Продолжает [семейный доступ](2026-10-25-family-access-design.md), где лента была вынесена за объём, и пункт 18.6 [функциональной спецификации](2026-08-30-family-budget-app-spec.md).

## Цель

Участник семьи, открыв приложение, видит, что за время его отсутствия сделали другие: какие расходы и доходы добавили, какие переводы и перемещения между конвертами провели, какие платежи оплатили, какие события календаря завели, кто вступил в семью или вышел из неё.

## Объём

- карточка «Что нового в семье» на главной: до 5 последних событий, число новых, ссылка «Все события»;
- страница `/app/activity`: новые события сверху, разделитель «Ранее», история за 30 дней по дням, фильтр по участнику, «Показать ещё»;
- пункт меню «Лента» со счётчиком новых событий;
- отметка «просмотрено» на пару «бюджет + пользователь», сдвигается при открытии страницы `/app/activity`.

Вне объёма (кандидаты на расширение):

- email-дайджест и push на основе ленты (пункт 18.6, отдельное решение владельца о внешней доставке);
- отметка «просмотрено» для отдельных событий;
- история глубже 30 дней (её роль выполняет журнал операций);
- события настроек, справочников, входов и демо-данных;
- фоновый опрос сервера для обновления счётчика.

## Решения владельца

| Вопрос | Решение |
|---|---|
| Что считать прошлым визитом | Открытие страницы ленты. Пока она не открыта, события остаются новыми |
| Где показывать | Карточка на главной и отдельная страница `/app/activity` |
| Какие события | Значимые для семьи: деньги, планы, календарь, состав семьи. Без технических |
| Глубина | Новые сверху, ниже история за 30 дней. Без отметки новыми считаются события за 7 дней |
| Источник данных | Существующий журнал `AuditEvent`, без новой записи в финансовых путях |
| Интерфейс | Из существующих компонентов Calm Fintech, без прототипа в Figma |

## Доступ

| Действие | `OWNER` | `EDITOR` | `VIEWER` |
|---|---|---|---|
| Читать ленту | да | да | да |
| Сдвинуть свою отметку | да | да | да |

Цепочка проверок прежняя: `requireAccessActor` (аутентификация, активное членство, доступ к бюджету). Чужой бюджет — 404, как в остальных `budgets/:budgetId` эндпоинтах. Отметка всегда своя: `userId` берётся из сессии, не из запроса.

## Данные

Новая таблица `activity_feed_cursors` (модель `ActivityFeedCursor`):

| Поле | Тип | Примечание |
|---|---|---|
| `id` | uuid | UUIDv7 |
| `workspaceId` | uuid | FK `workspaces` |
| `budgetId` | uuid | FK `budgets` |
| `userId` | uuid | FK `users` |
| `seenAt` | timestamptz(3) | время сервера на момент открытия ленты |
| `createdAt`, `updatedAt` | timestamptz(3) | |

Уникальный индекс `(budgetId, userId)`. Миграция аддитивная. Удаление аккаунта (`apps/worker/src/account-purge.ts`) и сброс бюджета (`docs/runbooks/budget-reset.sql`) удаляют строки вместе с бюджетом и пользователем.

Отметка не является финансовой записью: история не нужна, запись аудита о её сдвиге не создаётся.

## Источник событий

Лента читает `audit_events` по существующему индексу `(budgetId, createdAt)`. Все нужные записи уже содержат `budgetId`, в том числе события состава семьи (`workspace_membership`, `workspace_invitation` записывают активный бюджет семьи).

Белый список пар «`entityType` + `action`» и вид события ленты (`kind`):

| `entityType` | `action` | `kind` |
|---|---|---|
| `transaction` | `CREATED` | `TRANSACTION_CREATED` |
| `transaction` | `UPDATED` | `TRANSACTION_UPDATED` |
| `transaction` | `DELETED` | `TRANSACTION_DELETED` |
| `transaction` | `RESTORED` | `TRANSACTION_RESTORED` |
| `transfer` | `CREATED` | `TRANSFER_CREATED` |
| `transfer` | `DELETED` | `TRANSFER_DELETED` |
| `envelope-assignment` | `CREATED` | `ENVELOPE_FUNDED` |
| `envelope-movement` | `CREATED` | `ENVELOPE_MOVED` |
| `plan_occurrence` | `COMPLETED` | `PLAN_PAID` |
| `regular_plan` | `CREATED` | `PLAN_CREATED` |
| `calendar_event` | `CREATED` | `CALENDAR_EVENT_CREATED` |
| `calendar_event` | `UPDATED` | `CALENDAR_EVENT_UPDATED` |
| `calendar_event` | `DELETED` | `CALENDAR_EVENT_DELETED` |
| `workspace_invitation` | `ACCEPTED` | `MEMBER_JOINED` |
| `workspace_membership` | `LEFT` | `MEMBER_LEFT` |
| `workspace_membership` | `REMOVED` | `MEMBER_REMOVED` |

Имена действий сверены с путями записи v2 при подготовке плана: у операций нет отдельного `CANCELLED`, а `transfer` `UPDATED` хранит только изменённые поля, поэтому обе пары в белый список не входят. Пара без записи в коде в белый список не добавляется.

Белый список фильтруется в SQL-запросе (`OR` по парам), не после выборки. Собственные события исключаются в запросе (`actorUserId <> :me`). Записи без автора (`actorUserId IS NULL`, системные и worker) в ленту не попадают.

## Разбор записей

Каждый `kind` разбирается своей чистой функцией `(auditRow) => FeedDraft | null` в `apps/api/src/activity-feed/feed-parsers.ts`. Функция берёт из `oldValues`/`newValues` только нужные поля:

- суммы — из строки в `bigint` (`amountMinor`, `totalMinor`), в ответ уходят строкой минорных единиц;
- ссылки на счета, конверты, категории, план — идентификаторы для подстановки названий;
- для календаря — дата начала (`startsOn` или `startsAt`) из записи аудита; названия в аудите календаря нет, оно берётся из `calendar_events` по `entityId` внутри бюджета;
- для `PLAN_PAID` — только идентификатор вхождения: в v2 запись оплаты хранит лишь смену статуса, название плана берётся через вхождение, суммы у события нет;
- для `TRANSACTION_*` — вид операции (`EXPENSE`, `INCOME`) для фразы и тона иконки.

Если формат записи не распознан (нет обязательного поля, сумма не число), функция возвращает `null`, запись пропускается и пишется в лог на уровне `warn` с `auditEventId` без содержимого. Ответ из-за такой записи не падает.

Названия подставляются после разбора одним запросом на тип объекта на страницу, всегда с фильтром `budgetId`. Удалённые и архивные объекты подставляются под своим названием. Если объект не найден, используется метка: «удалённый счёт», «удалённый конверт», «без категории», «удалённый план», «удалённое событие».

Наружу не отдаются ни `oldValues`, ни `newValues`, ни `requestId`, ни `source`.

## API

Версия как у остальных `budgets/:budgetId` эндпоинтов (`v2`). Оба описаны в OpenAPI с ошибками 401, 403, 404.

`GET /api/v2/budgets/:budgetId/activity?cursor=&limit=&actorId=`

- `limit` от 1 до 30, по умолчанию 30;
- `actorId` — фильтр по участнику (uuid), необязательный;
- `cursor` — непрозрачная строка из `nextCursor`, сортировка `createdAt DESC, id DESC`;
- окно — 30 дней от текущего времени сервера.

Ответ:

```json
{
  "seenAt": "2026-10-29T18:00:00.000Z",
  "newSince": "2026-10-29T18:00:00.000Z",
  "unseenCount": 3,
  "people": [{ "userId": "…", "displayName": "Аня", "isActiveMember": true }],
  "items": [
    {
      "id": "…",
      "occurredAt": "2026-10-30T11:20:00.000Z",
      "kind": "TRANSACTION_CREATED",
      "isNew": true,
      "actor": { "userId": "…", "displayName": "Аня", "isActiveMember": true },
      "amountMinor": "120000",
      "currency": "RUB",
      "transactionType": "EXPENSE",
      "title": "Продукты",
      "details": ["Карта"],
      "target": null,
      "link": { "type": "TRANSACTION", "id": "…", "date": null }
    }
  ],
  "nextCursor": "…"
}
```

- `seenAt` — отметка пользователя или `null`, если её нет;
- `newSince` — граница новых: `seenAt`, без отметки — «сейчас минус 7 дней»; `isNew` и `unseenCount` считаются от неё;
- `people` — другие участники семьи, включая бывших: по нему веб скрывает карточку и строит фильтр;
- `unseenCount` учитывает белый список и исключение своих событий, но не фильтр `actorId`;
- `actor` и `target` — существующий `PersonRef`; веб подписывает их через `authorLabel`, бывший участник — «Имя (не в семье)»;
- `title` — категория, конверт, план или событие; `details` — счета и конверты по порядку показа;
- `target` заполнен только у `MEMBER_REMOVED`;
- `link` = `null`, если объект удалён: фронтенд не строит ссылку; `link.date` есть только у событий календаря (дата начала в поясе бюджета).

`POST /api/v2/budgets/:budgetId/activity/seen`

- тело пустое; ставит `seenAt` = время сервера (upsert по `(budgetId, userId)`);
- ответ `{ "seenAt": "…" }`;
- отметка только растёт: если сохранённое значение больше, оно остаётся;
- повтор безопасен, ключ идемпотентности не нужен.

Модуль `apps/api/src/activity-feed/`: контроллер (только HTTP), application service (доступ, окно, отметка, сборка ответа), репозиторий (запросы `audit_events`, названия, отметка), парсеры.

## Интерфейс

Только существующие компоненты и токены Calm Fintech, без новых цветов.

### Карточка на главной

`FamilyActivityCard` в `apps/web/app/components/dashboard/`:

- карточка в оформлении `RecentOperations`: заголовок «Что нового в семье», справа `UiStatus` «3 новых» при `unseenCount > 0` и `UiMoreLink` «Все события» на `/app/activity`;
- до 5 строк `ActivityRow`;
- стоит после «Ближайших платежей», перед конвертами;
- скрыта, если `people` пуст или запрос не удался: главная из-за ленты не ломается;
- пустое состояние — строка «Пока тихо — семья ничего не меняла.»;
- запрос `GET …/activity?limit=5`. Отметку карточка не сдвигает.

### Строка ленты

`ActivityRow` на основе `UiListRow`. У `UiListRow` появляется свойство `interactive` (по умолчанию `true`): при `false` строка рендерится блоком без кнопки и без события выбора.

- `leadingTone` по виду события: доход — зелёный, перевод — синий «информация», расход — нейтральный. Конверты, платежи, календарь и семья — нейтральные. Иконки — как у разделов меню: `Receipt`, `ArrowLeftRight`, `PiggyBank`, `CalendarClock`, `CalendarDays`, `Users`;
- заголовок — «Аня · добавлен расход», подпись — «Продукты · Карта · 14:20», справа сумма через `formatMinorUnits(minor, currency, 2)` и `tabular-nums`;
- у `TRANSACTION_DELETED` и `TRANSFER_DELETED` сумма зачёркнута, вторичным цветом, плюс видимый текст «удалено»;
- новые события — `UiStatus` «новое» (текст, не только цвет);
- строка открывает объект, если есть `link`: операция — журнал (`?operationId=`), перевод — журнал, конверт — «Конверты», платёж — «Планы» (`?occurrence=`), план — «Планы», событие — календарь (`?view=agenda&date=`). Иначе строка не интерактивна.

Фразы собирает фронтенд по `kind` в безличной форме, без согласования по роду:

| `kind` | Фраза |
|---|---|
| `TRANSACTION_CREATED` | добавлен расход / получен доход |
| `TRANSACTION_UPDATED` | изменён расход / изменён доход |
| `TRANSACTION_DELETED` | удалён расход / удалён доход |
| `TRANSACTION_RESTORED` | восстановлена операция |
| `TRANSFER_CREATED` | перевод |
| `TRANSFER_DELETED` | удалён перевод |
| `ENVELOPE_FUNDED` | пополнен конверт |
| `ENVELOPE_MOVED` | перемещение между конвертами |
| `PLAN_PAID` | оплачен платёж |
| `PLAN_CREATED` | новый план |
| `CALENDAR_EVENT_CREATED` | новое событие |
| `CALENDAR_EVENT_UPDATED` | изменено событие |
| `CALENDAR_EVENT_DELETED` | удалено событие |
| `MEMBER_JOINED` | в семье |
| `MEMBER_LEFT` | больше не в семье |
| `MEMBER_REMOVED` | исключён участник «Имя» |

Для `MEMBER_REMOVED` автор — создатель семьи, а имя исключённого берётся по `entityId` (членство) через тот же `PersonRef`.

Время в подписи: сегодня — «14:20», вчера — «вчера, 14:20», раньше — «28 окт, 14:20» (фиксированный список коротких месяцев, как в календаре).

### Страница `/app/activity`

- шапка как у других разделов: «Лента», подзаголовок «Что сделали другие участники за 30 дней»;
- фильтр участников — `UiFilterBar` с `UiChip` «Все» и именами, без горизонтальной прокрутки;
- блок «Новое», затем разделитель «Ранее», затем группы по дням («Сегодня», «Вчера», «28 октября»), каждая группа — карточка;
- «Показать ещё» — `UiButton variant="secondary"` по `nextCursor`;
- загрузка — `UiSkeleton`, пустое состояние — `UiEmptyState` «За 30 дней семья ничего не меняла»;
- при открытии страница сначала получает ленту, затем вызывает `seen`. Разделение «Новое»/«Ранее» на открытой странице остаётся по `newSince` из первого ответа, в том числе после смены фильтра и «Показать ещё»;
- ошибка загрузки — сообщение и кнопка «Повторить»; ошибка `seen` не показывается пользователю.

### Меню

Пункт «Лента» с иконкой `Activity` в сайдбаре и мобильном меню; нижняя навигация не меняется. Счётчик — общий `unseenCount` из запроса карточки или страницы; если его ещё никто не прочитал, сайдбар один раз за загрузку приложения запрашивает `limit=1`. Видимое число скрыто от экранного диктора, доступное имя ссылки — «Лента, 3 новых события». После `seen` счётчик обнуляется без повторного запроса. Фонового опроса нет.

## Доступность

- строки-ссылки и чипы работают с клавиатуры, видимый фокус из токенов;
- статус «новое» и «удалено» передаётся текстом, не только цветом;
- счётчик в меню имеет доступное имя;
- «Показать ещё» переносит фокус на первую новую строку;
- сенсорные цели не меньше 44px.

## Тесты

API, unit:

- каждый парсер на эталонных записях аудита, в том числе неполных и с устаревшим форматом (возвращает `null`);
- построение условия белого списка;
- курсор: кодирование, декодирование, отказ на испорченном курсоре (400).

API, integration:

- изоляция бюджета: события чужого бюджета не попадают в выборку, чужой `budgetId` — 404;
- свои события и события без автора не показываются;
- окно 30 дней и порог 7 дней без отметки;
- `seen` создаёт и сдвигает отметку, отметка не уменьшается, `unseenCount` считает только события после неё;
- `VIEWER` читает ленту и сдвигает свою отметку;
- фильтр `actorId` не влияет на `unseenCount`;
- бывший участник приходит с `isActiveMember = false`;
- отсутствующий счёт — «удалённый счёт», у удалённого объекта `link = null`;
- в ответе нет `oldValues`, `newValues`, `requestId`;
- удаление аккаунта и бюджета удаляет отметку;
- OpenAPI описывает оба эндпоинта.

Web, Vitest:

- фраза и иконка для каждого `kind`;
- форматы времени в подписи;
- группировка по дням и разделитель «Ранее»;
- пустое состояние, ошибка с «Повторить», фильтр, «Показать ещё»;
- страница вызывает `seen` после первой загрузки, ошибка `seen` не ломает страницу;
- карточка скрыта для одиночного пользователя;
- счётчик в меню и его доступное имя.

E2E (только CI): второй участник добавляет расход, первый видит его на главной и в ленте с пометкой «новое», после открытия ленты счётчик в меню исчезает.

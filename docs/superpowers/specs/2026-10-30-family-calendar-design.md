# Дизайн: семейный календарь

**Версия:** 1.0
**Дата:** 30.10.2026
**Статус:** утверждён владельцем, готов к плану реализации

## Контекст

Дизайн [семейного доступа](2026-10-25-family-access-design.md) заложил общее ядро «семья = workspace, участники и роли» и вынес семейный календарь в отдельный дизайн. **Решение владельца от 30.10.2026: семейный календарь входит в объём v1** по этому дизайну, как ранее семейный доступ. Остальные пункты раздела «После v1» функциональной спецификации остаются вне v1.

Календарь даёт семье одну картину недели: общие дела и расписания (кружки, врачи, праздники) и рядом — плановые платежи и поступления из «Планов», только для просмотра. Календарь не меняет финансовую логику и инварианты денег.

## Объём

Входит:

- события: название, описание, весь день или время начала и конца, участники-пометки, повторение, одно напоминание внутри приложения;
- лента «события + платежи» за диапазон дат, виды «Месяц» и «Повестка», фильтр «Все / Мои», переключатель «Платежи»;
- напоминания в существующем центре уведомлений через worker;
- ссылка из карточки платежа на обязательство в «Планах».

Вне объёма (кандидаты на расширение):

- правка или отмена одного повтора серии (исключения из серии);
- проведение плановой оплаты прямо из календаря;
- недельная сетка с часами;
- несколько напоминаний на событие, email/push/Telegram;
- передача событий бывшего участника создателю;
- календарь на уровне семьи при нескольких бюджетах (сейчас один бюджет на семью).

## Доступ

Правила продолжают этап B:

| Действие | `OWNER` | `EDITOR` | `VIEWER` |
|---|---|---|---|
| Видеть события и ленту | да | да | да |
| Создать событие | да | да | нет (403 `FORBIDDEN`) |
| Изменить или удалить событие | только своё | только своё | нет |

- Автор (`createdByUserId`) — единственный, кто изменяет и удаляет событие. Создатель семьи прав на чужие события не получает. Чужое событие — 403 `NOT_EVENT_AUTHOR`, `detail`: «Изменять событие может только его автор.»
- Участники события — пометка «для кого», прав не дают.
- События вышедшего или удалённого участника остаются видимыми с подписью автора по существующему правилу `authorLabel` («Алия (не в семье)») и не правятся никем. Создателю они не передаются.
- Бывший участник в списке участников прошлых событий остаётся с той же подписью; выбрать в новом событии можно только активных членов семьи.

## Данные

Календарь бюджета: события хранятся с `workspaceId` и `budgetId`, все запросы фильтруют `budgetId` в самом запросе.

`CalendarEvent` (`calendar_events`):

| Поле | Тип | Правило |
|---|---|---|
| `id` | uuid | uuid v7 |
| `workspaceId`, `budgetId` | uuid | связь `(budgetId, workspaceId)` с `Budget`, как у `Notification` |
| `createdByUserId` | uuid | автор |
| `title` | varchar(200) | обязателен, после trim не пуст |
| `description` | varchar(2000)? | необязателен |
| `allDay` | boolean | |
| `startsOn`, `endsOn` | date? | заданы, если `allDay`; `endsOn >= startsOn`; событие может длиться несколько дней (не дольше 31 дня) |
| `startsAt`, `endsAt` | timestamptz? | заданы, если не `allDay`; `endsAt >= startsAt`; длительность не больше 24 часов |
| `recurrence` | enum `CalendarRecurrence`: `NONE`, `DAILY`, `WEEKLY`, `MONTHLY`, `YEARLY` | |
| `interval` | int | 1–99, у `NONE` равен 1 |
| `weekdays` | int[] | ISO 1–7 (пн–вс); не пуст только у `WEEKLY` |
| `repeatUntil` | date? | только у повторяющихся; не раньше даты начала |
| `reminderMinutes` | int? | `15`, `60`, `1440`, `10080` или `null` |
| `deletedAt` | timestamptz? | логическое удаление |
| `createdAt`, `updatedAt` | timestamptz | |

Check-ограничения в миграции повторяют правила таблицы (взаимоисключение полей дня и времени, `interval`, `weekdays`, допустимые `reminderMinutes`). Индексы: `(budgetId, deletedAt)`, `(budgetId, createdByUserId)`, частичный `(budgetId) WHERE reminder_minutes IS NOT NULL AND deleted_at IS NULL`.

`CalendarEventParticipant` (`calendar_event_participants`): `(eventId, userId)` — первичный ключ, `budgetId` для фильтра и связи `(eventId, budgetId)`. Каскадное удаление не нужно: событие удаляется логически.

Новые enum-значения: `NotificationType.CALENDAR_REMINDER`, `WorkerJobType.EVALUATE_CALENDAR_REMINDERS`. Миграция только аддитивная, бэкфилла нет.

## Повторения

Вхождения не хранятся: чистая функция `expandOccurrences(event, window, timezone)` разворачивает правило в вхождения за диапазон.

- Повтор считается в локальном времени бюджета (`Budget.timezone`): «каждый вторник в 17:00» остаётся в 17:00 после перехода на летнее время. Для события со временем локальные дата и время начала вычисляются из `startsAt`, длительность сохраняется в минутах.
- `DAILY` — каждые `interval` дней от даты начала; `WEEKLY` — в дни `weekdays` каждые `interval` недель, недели считаются от понедельника недели начала; `MONTHLY` — число месяца даты начала, в коротком месяце — последний день месяца; `YEARLY` — та же дата, 29 февраля в невисокосный год — 28 февраля.
- Вхождение попадает в диапазон, если пересекается с ним (многодневное событие, начавшееся до `from`, тоже попадает). `repeatUntil` ограничивает дату начала вхождения включительно.
- `occurrenceDate` — локальная дата начала вхождения, она же его идентификатор в серии.
- Диапазон одного запроса — не больше 62 дней.

**Размещение кода.** В репозитории нет пакетов с исполняемым кодом: production-образ собирает `apps/*/src` в `dist`, а пакет с исходниками на TypeScript в `node_modules` Node не исполняет. Поэтому функция живёт в двух модулях — `apps/api/src/calendar/calendar-recurrence.ts` и `apps/worker/src/calendar-recurrence.ts` — как уже сделано для повторений планов. Расхождение исключает общий набор эталонных случаев `fixtures/calendar-recurrence/cases.json` в корне репозитория: оба набора unit-тестов прогоняют все случаи и сравнивают результат. Любое изменение правила меняет оба модуля и эталон в одном PR.

## API

Все эндпоинты — `/api/v2/budgets/:budgetId/calendar/...`, описаны в OpenAPI с запросами, ответами и кодами ошибок.

- `GET /calendar?from=YYYY-MM-DD&to=YYYY-MM-DD[&participantUserId=uuid][&includePlans=true|false]` — лента. Любой активный участник.
  - `items[]` в порядке: дата, затем «весь день» раньше событий со временем, затем время начала, затем название.
  - `kind: 'EVENT'`: `eventId`, `occurrenceDate`, `title`, `allDay`, `startsAt`/`endsAt` (ISO) или `startsOn`/`endsOn`, `recurrence`, `participants: PersonRef[]`, `createdBy: PersonRef`, `canEdit`.
  - `kind: 'PLAN'`: `occurrenceId`, `planId`, `planKind` (`OBLIGATION` | `INCOME_PLAN`), `title`, `amountMinor` (строка), `status` (статус вхождения плана), `isOverdue`, `owner: PersonRef`, `scheduledOn`. Источник — `PlansCalendarApplicationService.calendar` за каждый месяц, пересекающий диапазон (не больше трёх), с отбором по `scheduledOn`: суммы (`expectedMinor`), статусы и просрочка совпадают со страницей «Планы» по построению.
  - `participantUserId` — режим «Мои»: события, где пользователь автор или участник; платежи — где он владелец плана.
  - `includePlans=false` скрывает платежи.
  - Коды: 400 `VALIDATION_FAILED` (формат, `to < from`, диапазон больше 62 дней), 401, 404, 409 `MODEL_VERSION_MISMATCH`.
- `GET /calendar/events/:eventId` — событие с правилом повторения, участниками, `createdBy`, `canEdit`. 404 для чужого бюджета и удалённого события.
- `POST /calendar/events` — создать. Заголовок `Idempotency-Key` обязателен; повтор с тем же ключом и телом возвращает тот же ответ, с другим телом — 409 `IDEMPOTENCY_CONFLICT`. 201.
- `PATCH /calendar/events/:eventId` — изменить всю серию; тело полное, как при создании (форма всегда отправляет все поля). `Idempotency-Key` обязателен.
- `DELETE /calendar/events/:eventId` — логическое удаление серии. 204.

Тело создания: `title`, `description?`, `allDay`, `date` (`YYYY-MM-DD`), `endDate?` (для многодневного «весь день»), `startTime?`/`endTime?` (`HH:MM`, локальное время бюджета, обязательны без `allDay`), `recurrence`, `interval?`, `weekdays?`, `repeatUntil?`, `participantUserIds[]`, `reminderMinutes?`. Сервер переводит локальные дату и время в `startsAt`/`endsAt` по часовому поясу бюджета.

Порядок проверок в мутации — как на этапе B: `planModelPolicy.requireModel` (404 для чужого бюджета) → транзакция, `lockBudget` → idempotency → `requireAccessActor` (403 `FORBIDDEN` для `VIEWER` и бывшего участника) → загрузка события с `budgetId` и `deletedAt: null` (404) → `BudgetAccessPolicy.requireEventAuthor` (403 `NOT_EVENT_AUTHOR`) → валидация → запись и `AuditEvent` (`entityType: 'calendar_event'`, `CREATED`/`UPDATED`/`DELETED`).

Валидация — 400 `VALIDATION_FAILED` с ошибками по полям (схема zod); участник не активный член этой семьи — 422 `PARTICIPANT_NOT_MEMBER`.

## Напоминания

- Новая задача worker `EVALUATE_CALENDAR_REMINDERS` (`jobKey: 'calendar:reminders-v1'`), интервал 5 минут, в существующем механизме `WorkerJob`.
- Задача выбирает события с `reminderMinutes`, не удалённые, и разворачивает вхождения в окне `[now − 30 мин, now + reminderMinutes + 30 мин]`. Напоминание создаётся, если момент `начало вхождения − reminderMinutes` лежит в `(now − 30 мин, now]`. Если worker простаивал дольше, старые напоминания не создаются.
- Началом события на весь день считается 09:00 по часовому поясу бюджета.
- `NotificationType.CALENDAR_REMINDER` получают автор и участники, только активные члены семьи.
- Ключ `calendar:<eventId>:<occurrenceDate>:<reminderMinutes>` в уникальном индексе `(budgetId, userId, notificationKey)`; запись через `createMany({ skipDuplicates: true })`, повтор запуска не создаёт дубль. Смена времени события не даёт второго напоминания для того же вхождения; смена `reminderMinutes` даёт новый ключ.
- Заголовок — название события; текст — «Сегодня в 17:00», «Завтра в 09:30», «Завтра, весь день», «6 ноября в 17:00», «6 ноября, весь день». `relatedEntityType: 'calendar_event'`, `relatedEntityId: eventId`, `actionPath: '/app/calendar?date=YYYY-MM-DD'`.
- Удалённое событие и вхождения после `repeatUntil` напоминаний не дают; уже созданные уведомления остаются.

## Интерфейс

Утверждён по прототипу Figma AI (30.10.2026) с правками ниже. Все решения — по [Calm Fintech](2026-09-17-calm-fintech-visual-guidelines.md).

**Навигация.** Пункт «Календарь» (`/app/calendar`, иконка `CalendarDays`) в `AppSidebar` и `AppMobileMenu` сразу после «Планов».

**Шапка страницы.** Надзаголовок «Семейный календарь», заголовок «Календарь». Справа: `UiButtonGroup` «Месяц / Повестка»; навигация «‹ Октябрь 2026 ›» (в «Повестке» — шаг 14 дней и подпись диапазона «30 окт – 12 ноя») и кнопка «Сегодня»; `UiButtonGroup` «Все / Мои» (только если в семье больше одного человека); переключатель «Платежи»; основная кнопка «Новое событие» (нет для `VIEWER`). Переключателя темы в шапке нет — он в сайдбаре. На ширине меньше 1024px переключатели — отдельной строкой, навигация под ними, «Новое событие» — icon-only `+` с `aria-label`; горизонтальной прокрутки нет.

Вид по умолчанию: «Месяц» от 1024px, «Повестка» ниже. Выбор хранится в query (`?view=month|agenda&date=YYYY-MM-DD`).

**Месяц.** Карточка с сеткой 7×N, неделя с понедельника, дни соседних месяцев приглушены. В ячейке до трёх строк, затем «+ ещё N»:

- событие — текст «17:00 Кружок рисования» или «Весь день · День рождения бабушки»;
- платёж — плашка с иконкой `Wallet` и «Аренда · 45 000 ₽»; доход — иконка `ArrowDownLeft`, сумма «+120 000 ₽» без окраски текста; просрочка — иконка `AlertCircle`, слово «просрочен» и тёплый фон.

Сегодня — кольцо вокруг числа; фокус — рамка ячейки. Сетка — `role="grid"`, стрелки двигают фокус по дням, `Enter` открывает панель дня; у ячейки `aria-label` «30 октября, 3 события, 1 платёж». Клик по дню открывает **панель дня** — `UiModal` «Четверг, 30 октября»: время слева или «Весь день», название, участники текстом, «Автор: Алия»; у платежа — сумма и статус справа, «Владелец: Ильдар». Футер: «Закрыть», «Новое событие на этот день» (нет для `VIEWER`).

**Повестка.** Лента на 14 дней от выбранной даты, группы по дням («Сегодня, чт 30 октября», «Завтра, пт 31 октября», «Вт 4 ноября»), пустые дни пропускаются; строки — `UiListRow` в карточке группы: плашка-иконка (`CalendarDays` для события, `Wallet` для платежа), название, подпись «17:00 · Алия, Ильдар» или «12 500 ₽», статус платежа — только `UiStatus`-пилюлей справа (не дублируется в подписи), шеврон. Внизу «Показать ещё» — следующие 14 дней. Пустая лента — `UiEmptyState` «На эти дни ничего не запланировано».

**Подписи участников.** Через `authorLabel`; если участники — все активные члены семьи, подпись «Вся семья».

**Карточка события** — `UiModal size="sm"`, заголовок — название. Строки: `Repeat` + «Каждый вторник, 17:00–18:30» и «Повторяется до 29 декабря» (для неповторяющегося — `CalendarDays` + дата и время); `Users` + участники; `Bell` + напоминание; «Автор: Ильдар»; «Описание». Своё событие — в шапке icon-only «Изменить» (`Pencil`, tooltip) и `UiActionMenu` с «Удалить»; удаление — `UiConfirmDialog` «Удалить событие и все его повторы?» («Отмена», «Удалить»). Чужое — без действий, с плашкой `Info` «Автор: Алия. Изменять событие может только автор». Событие бывшего участника — «Автор: Алия (не в семье)».

**Карточка платежа** — `UiModal size="sm"`: иконка `Wallet`, «Сумма», статус-пилюля, «Владелец: Ильдар», ссылка `UiMoreLink` «Открыть в «Планах» →» на `/app/plans?occurrence=<occurrenceId>`.

**Форма события** — `UiModal` (40rem, на телефоне на весь экран), «Новое событие» / «Изменить событие»: «Название»; переключатель «Весь день» с подсказкой «Событие без времени начала и конца»; «Дата» (`UiDatePicker`); для «весь день» необязательная «Дата окончания»; «Начало» и «Конец» — `UiInput type="time"` (шаг 5 минут) в одну строку; «Повторять» (`UiSelect`): «Не повторять / Каждый день / Каждую неделю / Каждый месяц / Каждый год»; для недели — блок на подложке с днями «Пн … Вс» чипами (`aria-pressed`, по умолчанию день даты начала) и «Повторять до» (`UiDatePicker`, «необязательно»); «Участники» — чипы активных членов семьи с галочкой у выбранных; «Напоминание» (`UiSelect`): «Без напоминания / За 15 минут / За 1 час / За 1 день / За 1 неделю»; «Описание» («необязательно»). Ошибки — под полем (в том числе с сервера по `fieldErrors`). Футер: «Отмена», «Сохранить событие». Новое событие из панели дня подставляет дату.

**Уведомление.** `NotificationCard` для `CALENDAR_REMINDER`: иконка `Bell`, заголовок, текст и ссылка «Открыть в календаре →» по `actionPath`.

Тёмная тема — через существующие токены; новые цвета не вводятся. Тип элемента всегда обозначен иконкой и текстом, не только цветом. Касательные цели на телефоне — не меньше 44px.

## Тестирование

- Unit (api и worker): `expandOccurrences` на эталоне `fixtures/calendar-recurrence/cases.json` — все типы повторов, `interval`, `weekdays`, `repeatUntil`, 31-е в коротком месяце, 29 февраля, переход на летнее время (`Europe/Berlin`, `America/New_York`) и пояс без него (`Europe/Moscow`), многодневные события, пересечение с границей диапазона; правило напоминаний (окно, весь день в 09:00, тексты).
- Integration (api, `FamilyTestApp`): изоляция бюджетов (чужой бюджет 404, событие другого бюджета 404 по id); роли (`VIEWER` 403 `FORBIDDEN`, `EDITOR` правит своё, чужое — 403 `NOT_EVENT_AUTHOR`, создатель не правит чужое); бывший участник (события видны, `canEdit: false`, правка 403); валидация по полям и 422 `PARTICIPANT_NOT_MEMBER`; idempotency `POST`/`PATCH`; логическое удаление и `AuditEvent`; лента (порядок, «Мои», `includePlans`, лимит 62 дня, суммы и статусы платежей совпадают с `PlansCalendar` за тот же месяц); OpenAPI-контракт.
- Worker: напоминание в окне и не вне его; повторный запуск без дублей; весь день — 09:00 по поясу бюджета; получатели — автор и активные участники; удалённое событие и `repeatUntil`; простой дольше 30 минут без потока старых уведомлений.
- Web unit: форма (состояния «весь день» и повтор, ошибки по полям, дата из панели дня), «Вся семья», «+ ещё N», карточка чужого события только для чтения, нет «Нового события» у `VIEWER`, переключатель «Платежи», навигация повестки по 14 дней.
- E2E `e2e/family-calendar.spec.ts` (только CI): создатель заводит еженедельное событие с участницей; участница видит его в повестке без действий правки и создаёт своё; сценарий на 390px в тёмной теме.

# Уведомления в Telegram — дизайн

Дата: 31.10.2026. Статус: согласован владельцем. Второй подпроект внешней доставки после [уведомлений на почту](2026-10-31-email-notifications-design.md), пункт 18.3 [функциональной спецификации](2026-08-30-family-budget-app-spec.md). Решением владельца от 31.10.2026 уведомления в Telegram переносятся в объём. Ввод операций и событий календаря через бота (подпроект 3) и web push (подпроект 4) остаются вне объёма.

## Цель

Участник семьи получает в личный чат с ботом HarmoFin то же, что может получать на почту: срочные сообщения о просроченном платеже и напоминания календаря, а также дайджест событий семьи. Привязка чата к аккаунту делается одноразовой ссылкой после явного согласия, сообщения идут через общую очередь доставки, кнопки в сообщениях ведут в приложение.

## Объём

- привязка личного чата Telegram к аккаунту через `https://t.me/<бот>?start=<код>` с согласием;
- отвязка из веба, командой `/stop` и блокировкой бота;
- настройки канала `TELEGRAM`: главный переключатель, срочные, дайджест (выключен / ежедневно / еженедельно), суммы по отдельному согласию;
- срочные сообщения `PLAN_OVERDUE` и `CALENDAR_REMINDER`, дайджест в 08:00 по часовому поясу бюджета — по тем же правилам, что у email;
- обобщение очереди доставки и задачи дайджеста на несколько каналов;
- webhook Telegram в API и скрипт регистрации webhook при деплое;
- страница настроек `/app/settings/telegram`.

Вне объёма (кандидаты на расширение):

- ввод операций и событий календаря из чата (подпроект 3);
- групповые чаты, несколько чатов на пользователя;
- другие типы уведомлений как отдельные сообщения;
- подтверждение платежа кнопкой в чате (только ссылка в приложение);
- библиотеки ботов (grammY, telegraf) и отдельный сервис бота;
- режим long polling для локальной разработки.

## Решения владельца

| Вопрос | Решение |
|---|---|
| Состав сообщений | Как в email: срочные и дайджест, настройки канала независимы от email |
| Входящие обновления | Webhook в API на production-домене |
| Суммы | По умолчанию без сумм; отдельный переключатель и согласие для Telegram |
| Куда привязывать | Один личный чат на пользователя; новая привязка заменяет старую; группы не поддерживаются |
| Реализация | Свой тонкий клиент Bot API на `fetch`, без новых зависимостей |

## Доступ и приватность

- Сообщения уходят только в привязанный личный чат. Получатель — активный участник бюджета на момент отправки; права перепроверяются при каждой отправке, как у email.
- Согласие на привязку обязательно: текст объясняет, что сообщения проходят через серверы Telegram — стороннего сервиса. Время согласия хранится в коде привязки и в привязке.
- Суммы — только при `include_amounts` канала `TELEGRAM` с отдельным согласием (`amounts_consent_at`); согласие email на Telegram не распространяется. Текст сообщения собирается при отправке и не хранится.
- Имя, username и профиль Telegram не хранятся; хранится только `chat_id`.
- `chat_id`, код привязки, токен бота, текст сообщений и суммы не попадают в логи, метрики и аудит. Токен бота входит в URL запроса к Bot API, поэтому URL запроса не логируется и не попадает в тексты ошибок.
- Аудит: `TELEGRAM_LINK_REQUESTED` (выдача ссылки), `TELEGRAM_LINKED`, `TELEGRAM_UNLINKED` с причиной (`web`, `stop`, `blocked`, `replaced`), изменение настроек канала, выдача и отзыв согласия на суммы.
- До выпуска владелец проверяет правовую сторону: передача данных через Telegram, вероятно, является трансграничной передачей ПД по 152-ФЗ. Нужны цель «уведомления в Telegram» в [политике обработки ПД](2026-10-18-legal-documents-design.md), новая версия текста согласия и, при необходимости, уведомление Роскомнадзора. Это не блокирует разработку, но блокирует релиз.

## Привязка

1. На странице `/app/settings/telegram` пользователь видит текст согласия с флажком и кнопку «Подключить Telegram».
2. `POST /api/v1/me/telegram/link` с `{consent: true}`: сервер гасит прежние неиспользованные коды пользователя, создаёт новый (32 случайных байта, `base64url`, 43 символа — подходит под ограничение параметра `start`: до 64 символов `A-Za-z0-9_-`), хранит HMAC через `TokenService`, срок 15 минут. Ответ: `{url: "https://t.me/<бот>?start=<код>", expiresAt}`.
3. Веб показывает ссылку «Открыть Telegram» (новая вкладка, `rel="noopener noreferrer"`) и опрашивает `GET /api/v1/me/notification-settings/telegram` раз в 3 секунды, пока не увидит `linked: true` или не истечёт срок кода.
4. Пользователь нажимает Start, Telegram присылает на webhook `message` с текстом `/start <код>`.
5. API принимает только `chat.type = private`. Код ищется по HMAC, должен быть неиспользованным и не просроченным; код гасится, привязка создаётся или заменяет прежнюю привязку этого пользователя (аудит `TELEGRAM_UNLINKED` с причиной `replaced` для прежней). Если чат уже привязан к другому пользователю — привязка не создаётся.
6. Бот отвечает в чат:
   - успех: «Аккаунт HarmoFin привязан. Включите уведомления в настройках приложения.» с кнопкой «Настройки»;
   - неверный или просроченный код: «Ссылка устарела. Получите новую в настройках HarmoFin.»;
   - чат занят: «Этот чат уже привязан к другому аккаунту HarmoFin.»;
   - групповой чат: ответ не отправляется.
7. `/start` без кода и любые другие сообщения получают подсказку: «Чтобы подключить уведомления, откройте настройки HarmoFin. Отключить — /stop.»

Отвязка:

- `DELETE /api/v1/me/telegram/link` из веба (причина `web`);
- команда `/stop` в чате (причина `stop`), бот отвечает «Уведомления отключены.»;
- `my_chat_member` с новым статусом `kicked` (причина `blocked`);
- ответ Bot API 403 или `400 chat not found` при отправке (причина `blocked`).

Во всех случаях в одной транзакции: удаляется строка `telegram_links`, канал `TELEGRAM` выключается (`enabled = false`), записи очереди `TELEGRAM` в статусе `PENDING` получают `CANCELLED`, пишется аудит.

## Данные

Новая миграция, только добавление.

- `NotificationChannel` получает значение `TELEGRAM` (`ALTER TYPE ... ADD VALUE`).
- `WorkerJobType` не меняется: задача `BUILD_EMAIL_DIGESTS` (ключ `notifications:build-email-digests-v1`) сохраняет имя и строит дайджесты всех каналов; переименование не стоит миграции enum.
- Настройки канала — в существующей `notification_channel_settings` строкой с `channel = TELEGRAM`.

`telegram_links`:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | |
| `user_id` | uuid, FK `users`, unique | владелец привязки |
| `chat_id` | bigint, unique | личный чат Telegram |
| `consented_at` | timestamptz | согласие на привязку |
| `linked_at` | timestamptz | |
| `created_at`, `updated_at` | timestamptz | |

`telegram_link_codes`:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid | |
| `user_id` | uuid, FK `users` | |
| `code_hash` | char(64), unique | HMAC кода через `TokenService` |
| `consented_at` | timestamptz | согласие при выдаче кода |
| `expires_at` | timestamptz | +15 минут |
| `consumed_at` | timestamptz, null | |
| `created_at` | timestamptz | |

Индекс `(user_id, consumed_at, expires_at)`. Использованные и просроченные коды старше 1 дня удаляются задачей дайджеста вместе с очисткой очереди.

Привязка и коды относятся к пользователю, а не к бюджету: в v1 у пользователя один бюджет семьи. Записи очереди по-прежнему несут `workspace_id` и `budget_id` события.

## Очередь и отправка

Обобщение существующего кода email (`apps/worker/src/delivery/`):

- `enqueueUrgentEmail` становится `enqueueUrgent`: в той же транзакции, что и уведомление, ставит по одной записи на каждый канал получателя с `enabled` и `urgent_enabled`. `dedupe_key` прежний (`urgent:<notificationId>`), уникальность уже включает канал.
- Задача дайджеста строит записи для каждого настроенного в воркере канала по его `digest_frequency`; окно считается от прошлого дайджеста того же канала (сейчас поиск прошлого дайджеста не фильтрует канал — исправляется).
- `DeliveryRepository.claim` выбирает записи всех каналов.
- `DELIVER_NOTIFICATIONS` передаёт запись отправителю канала через интерфейс `ChannelSender` (`EmailSender` — текущая логика письма и токена отписки, `TelegramSender` — новый).
- Перепроверка зависит от канала: `EMAIL` — подтверждённая почта; `TELEGRAM` — существующая привязка. Общее: участник активен, канал и нужная опция включены, уведомление не закрыто. Воркер выбирает из очереди только каналы, для которых у него есть отправитель: без токена бота записи `TELEGRAM` остаются в очереди до его появления (как письма без SMTP).

Ответы Bot API в `TelegramSender`:

| Ответ | Действие |
|---|---|
| `200`, `ok: true` | `SENT`, `sent_at` |
| `429` | следующая попытка через `parameters.retry_after` секунд, `attempts` не растёт |
| `403` или `400` с описанием `chat not found` | отвязка (причина `blocked`), запись `CANCELLED` с причиной `TELEGRAM_CHAT_UNAVAILABLE` |
| прочие `4xx` | `FAILED` без повторов |
| `5xx`, таймаут, сеть | повторы 1 мин, 5 мин, 30 мин, 2 ч; после 5-й неудачи `FAILED` |

`last_error` хранит только `error_code` Telegram или класс ошибки. Таймаут запроса 10 секунд. Лимиты Telegram (около 30 сообщений в секунду на бота) при пачке 20 записей в минуту не достигаются, отдельный ограничитель не нужен.

## Сообщения

- `sendMessage` с `parse_mode: HTML`, `link_preview_options: {is_disabled: true}`; имена и названия экранируются (`&`, `<`, `>`).
- Срочное: жирный заголовок «Просрочен платёж «Ипотека»» или «Напоминание: «Родительское собрание»», ниже текст уведомления (с согласием — сумма); кнопка «Открыть» на `actionPath` уведомления. Без эмодзи.
- Дайджест: заголовок «Что нового в семье за 31 октября» или «за неделю», строки по людям как в письме, блок «Платежи сегодня»; кнопки «Открыть ленту» (`/app/activity`) и «Настройки» (`/app/settings/telegram`).
- Последняя строка: «Отключить: /stop или в настройках».
- Подсчёт содержимого общий с email (`digest-content.ts`, `urgent-content.ts`); шаблоны Telegram отдельные (`apps/worker/src/telegram/templates.ts`).
- Кнопки — `inline_keyboard` с `url`. Telegram принимает в кнопках только `https`; если `WEB_BASE_URL` не `https` (локальная разработка), кнопки не ставятся.

## API

Все эндпоинты и ошибки описаны в OpenAPI, в `/api/v1` рядом с настройками email.

- `GET /api/v1/me/notification-settings/telegram` — настройки канала (или значения по умолчанию), `available` (бот настроен на сервере), `linked`.
- `PUT /api/v1/me/notification-settings/telegram` — CSRF; тело `{enabled, urgentEnabled, digestFrequency, includeAmounts, amountsConsent?}`. `enabled: true` без привязки — 409 `TELEGRAM_NOT_LINKED`; `includeAmounts` без `amountsConsent: true` — 422 `AMOUNTS_CONSENT_REQUIRED`.
- `POST /api/v1/me/telegram/link` — сессия, CSRF, ограничение частоты; тело `{consent: true}` (иначе 422 `TELEGRAM_CONSENT_REQUIRED`); ответ `{url, expiresAt}`; бот не настроен — 409 `TELEGRAM_UNAVAILABLE`.
- `DELETE /api/v1/me/telegram/link` — сессия, CSRF; 204, в том числе если привязки нет.
- `POST /api/v1/telegram/webhook` — без сессии и CSRF. Заголовок `X-Telegram-Bot-Api-Secret-Token` сравнивается с `TELEGRAM_WEBHOOK_SECRET` через `timingSafeEqual`; несовпадение или отсутствие — 401. Иначе всегда 200 с пустым телом, в том числе для нераспознанных обновлений, чтобы Telegram не повторял их. Обрабатываются только `message` и `my_chat_member`. Ответы бота отправляются отдельным вызовом `sendMessage`; сбой ответа не отменяет привязку.

`OriginGuard` сейчас глобальный (`apps/api/src/app.ts`) и не знает исключений. Добавляется декоратор `@ExternalWebhook()` и проверка через `Reflector`: Origin не требуется только у маршрутов с этим декоратором. Webhook защищён секретным заголовком; `request_body max_size 1MB` в Caddy остаётся.

Клиент Bot API в API и воркере — небольшой модуль на `fetch` (`sendMessage`, `setWebhook` только в скрипте). Копия в двух приложениях допустима, как у хеша токена отписки; в клиент-общие пакеты он не выносится.

## Конфиг и инфраструктура

- API: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` (не короче 32 символов, только `A-Za-z0-9_-`).
- Воркер: `TELEGRAM_BOT_TOKEN`.
- Все три переменные необязательны, но задаются вместе: без них канал недоступен (`available: false`), webhook отвечает 404. Необязательная `TELEGRAM_API_BASE_URL` (по умолчанию `https://api.telegram.org`) нужна тестам и E2E.
- Переменные добавляются в `.env.example`, `infra/env/staging.example`, `infra/compose/production.yml` и секреты CI/CD.
- Скрипт `infra/scripts/telegram-webhook.sh` вызывает `setWebhook` с `url = $WEB_BASE_URL/api/v1/telegram/webhook` (только `https`), `secret_token`, `allowed_updates: ["message", "my_chat_member"]`, `drop_pending_updates: true`. Скрипт идемпотентный, токен не выводит; `deploy.sh` вызывает его после smoke, если задан `TELEGRAM_BOT_TOKEN`. Ошибка скрипта не откатывает деплой, но выводится как предупреждение.
- Для staging — отдельный бот и отдельный токен.
- Caddy уже проксирует `/api/*`, правки не нужны.
- Локально webhook не регистрируется: путь привязки проверяется тестами, вызывающими webhook напрямую с секретом.

## Интерфейс

Пункт «Уведомления в Telegram» в `/app/settings`, страница `/app/settings/telegram`:

- бот не настроен: пояснение «Telegram-бот пока не подключён на сервере», без действий;
- без привязки: текст согласия, флажок «Согласен», кнопка «Подключить Telegram» (недоступна без флажка); после нажатия — ссылка «Открыть Telegram», подсказка «Нажмите Start в Telegram» и статус ожидания с `aria-live`; по истечении срока — «Ссылка устарела», кнопка подключения снова доступна;
- с привязкой: «Telegram подключён», те же поля, что на странице email (разметка копируется, страница почты не меняется), диалог согласия на суммы с упоминанием Telegram, кнопка «Отключить Telegram» с подтверждением.

Calm Fintech: карточка как у страницы email, без цветового кодирования; клавиатура, видимый фокус, подписи у полей, статус не только цветом.

## Тесты

- Юниты API: разбор `/start <код>` и `/stop`, сравнение секрета, выбор ответа бота, проверка `chat.type`.
- Юниты воркера: шаблоны Telegram без сумм и с суммами, экранирование, кнопки только при `https`, разбор ответов Bot API (429 с `retry_after`, 403, `chat not found`, 4xx, 5xx, таймаут).
- Интеграция API: привязка через имитацию webhook, просроченный и повторно использованный код, чат занят другим пользователем, замена привязки, групповой чат, `/stop`, `kicked`, 401 без секрета, 404 без токена, отвязка из веба отменяет очередь, 409 и 422 в настройках, OpenAPI.
- Интеграция воркера: срочное и дайджест одновременно в `EMAIL` и `TELEGRAM` с подменённым клиентом; каналы не мешают друг другу; 403 отвязывает и отменяет; без токена бота записи `TELEGRAM` отменяются.
- Веб: страница в трёх состояниях, флажок согласия, опрос и истечение срока, диалог сумм, отвязка.
- E2E в CI: привязка вызовом webhook из теста с секретом, включение канала, отвязка. Настоящий Telegram не используется.

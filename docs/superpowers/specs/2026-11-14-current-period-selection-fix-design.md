# Исправление выбора текущего периода — 14.11.2026

## Цель и границы

Убрать две отметки текущего периода и восстановить автоматический выбор конверта операции, когда расход из другой половины создал у неё период с датами текущей половины. Основание: функциональная спецификация §21.4, модель Envelope Plan v2.2 §5.1, существующая серверная поддержка расходов по выбранному конверту.

## Подходы

- Переписывать даты и расходы: меняет историю и финансовый учёт, для этой ошибки не требуется.
- Выбирать первый конверт в браузере: скрывает неоднозначный серверный ответ, зависит от сортировки.
- Выбранный подход: уточнить серверный `periods[].current` по датам и текущему слоту бюджета. Использовать `cycleAndPeriodAt`, учитывающий ревизии цикла, и сегодняшний день в часовом поясе бюджета.

## Решение

Период с FIRST/SECOND является текущим, только если покрывает сегодня и его слот совпадает с действующей половиной цикла. Для периода без слота правило по датам сохраняется. Слот читается через связь периода с конвертом внутри уже ограниченного бюджетом запроса. Денежные строки прошлых и других половин остаются видимыми; суммы и история не меняются. Формат API не меняется.

Исправление не запрещает расходы из другой половины и не переносит их. Исправление существующих данных на продакшне для выбора текущего конверта не требуется. После выпуска следует обновить страницу приложения, чтобы перечитать справочники.

# HarmoFin — UX Workflow и структура приложения

## 1. Главный UX-принцип

Пользователь должен постоянно получать ответ на три вопроса:

### 1. Где мои деньги?

→ **Счета**

### 2. На что они предназначены?

→ **Конверты**

### 3. Сколько я могу потратить сейчас?

→ **Текущий период / доступный лимит**

Из этого строится вся навигация.

---

# 2. Основной workflow пользователя

Базовый сценарий:

```text
ПОЛУЧИЛ ДОХОД
      ↓
Добавил доход
      ↓
Распределил деньги
      ↓
      ├─────────────┐
      ↓             ↓
Обязательные     Текущие
      ↓             ↓
      └──────┬──────┘
             ↓
         Расходы
             ↓
       Остаток периода
             ↓
     Следующая выплата
             ↓
       Новый цикл
```

Отдельные сценарии:

```text
Добавил расход
      ↓
Выбрал категорию
      ↓
Выбрал конверт
      ↓
Система пересчитала:
  • счёт
  • конверт
  • лимит периода
  • аналитику
```

И:

```text
Создал накопительную цель
        ↓
Пополнял её
        ↓
Деньги находятся на счёте
        ↓
Но назначены конверту
        ↓
Можно использовать только по назначению
```

# 4. Mobile navigation

На смартфоне не пытаться сохранить весь sidebar.

Использовать:

```text
┌─────────────────────────────┐
│                             │
│        content              │
│                             │
│                             │
├─────────────────────────────┤
│ Главная Операции + Ещё      │
└─────────────────────────────┘
```

Основные действия:

- Главная
- Операции
- Большая кнопка `+`
- Ещё

`+` открывает:

```text
+ Добавить

Доход
Расход
Перевод
```

Кнопка добавления операции должна быть доступна с любого основного экрана максимум за один переход — это прямо предусмотрено ТЗ.

# 12. Workflow «Добавить доход»

Форма:

```text
Добавить доход

Сумма
[ 106 000 ₽ ]

Счёт
[ Основная карта ]

Категория
[ Зарплата ]

Дата
[ 10.09.2026 ]

          [Сохранить и распределить]
```

После сохранения автоматически открыть:

### Распределение дохода

```text
Доход

106 000 ₽

Куда направить?

Обязательные       50 000 ₽
Текущие 25–9       36 000 ₽
Ремонт             20 000 ₽

Нераспределено          0 ₽

              [Готово]
```

Это принципиально важный workflow.

Не заставлять пользователя вручную:

1. создать доход;
2. закрыть форму;
3. найти доход;
4. нажать «распределить».

Лучше:

> **Сохранил доход → сразу распределил.**

При этом внутри backend остаётся одна операция дохода + отдельные distributions, как предусмотрено моделью.

# 25. Настройка финансового цикла

Отдельный хороший onboarding-like экран.

```text

[ 25 ] числа
```

# 44. Warning States

Финансовое приложение не должно молча показывать проблемы.

Пример:

```text

−4 500 ₽

Проверьте распределение денег или операции.

[Посмотреть]
```

ТЗ предусматривает предупреждения при отрицательных остатках и дефицитах.

# 45. Critical workflow — недостаток денег

Например пользователь хочет потратить 20 000 ₽, но в конверте только 15 000 ₽.

Показать:

```text
Недостаточно средств

В конверте:
15 000 ₽

Расход:
20 000 ₽

Дефицит:
5 000 ₽

[Продолжить]
[Отмена]
```

Если включён строгий режим:

```text
Расход невозможно сохранить.

В конверте недостаточно средств.
```

Это поддерживается настройкой разрешения отрицательных остатков.

# 46. Transfer Workflow

Перевод должен быть простой формой.

```text
Новый перевод

Откуда
[Основная карта]

Куда
[Накопительный]

Сумма
[20 000 ₽]

Конверт

Ремонт          15 000 ₽
Обязательные     5 000 ₽

[Добавить часть]

────────────────────

Итого
20 000 ₽

[Перевести]
```

Система должна проверять:

```text
Σ частей = общая сумма
```

Это прямо закреплено в правилах переводов.

# 47. Важная UX-деталь переводов

Если пользователь переводит деньги:

```text
Карта → Накопительный
```

и конверт не меняет:

> **назначение денег сохраняется.**

Не заставлять пользователя повторно выбирать конверт, если он не хочет его менять.

По умолчанию конверт назначения должен совпадать с исходным.

# 56. Самое важное решение

Главная страница приложения **не должна выглядеть как банковское приложение**.

Она должна выглядеть скорее как:

> **financial control center**

То есть первым элементом является не список транзакций и не общий баланс, а:

```text
       МОЖНО ПОТРАТИТЬ

            21 800 ₽

          Осталось 7 дней

        ≈ 3 114 ₽ / день
```

А уже ниже пользователь может разобраться:

> где деньги → на что они назначены → какие платежи впереди → какие операции произошли.

Так HarmoFin получает собственную UX-модель вместо очередного «красивого приложения для учёта расходов».

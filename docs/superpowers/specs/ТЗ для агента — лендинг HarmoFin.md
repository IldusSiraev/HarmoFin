# HarmoFin — реализация продающего лендинга

## 1. Цель задачи

Реализовать современный адаптивный маркетинговый лендинг для продукта **HarmoFin** — веб-приложения для управления личными и семейными финансами.

Лендинг должен:

1. Понятно объяснять ценность продукта за первые 5–10 секунд.
2. Показывать отличие HarmoFin от обычных приложений для учёта расходов.
3. Демонстрировать интерфейс продукта через реалистичные UI-макеты.
4. Формировать доверие к финансовому продукту.
5. Подводить пользователя к регистрации / началу использования продукта.
6. Корректно работать на desktop, tablet и mobile.
7. Быть готовым к дальнейшему подключению реального backend/API без необходимости переделывать структуру страницы.

---

# 2. Источники истины

При реализации использовать следующие источники в таком порядке приоритета:

1. Данное ТЗ.
2. Основное ТЗ продукта HarmoFin.
3. Предложенный wireframe лендинга.
4. Визуальный mockup лендинга.
5. Общие UX/UI практики — только там, где они не противоречат данным выше.

Основное ТЗ продукта фиксирует следующие ключевые принципы:

- счёт отвечает на вопрос «где находятся деньги»;
- конверт отвечает на вопрос «на что предназначены деньги»;
- фактические доходы не должны зависеть от плановых значений;
- финансовый цикл не обязан совпадать с календарным месяцем;
- доступный лимит рассчитывается по фактическим операциям;
- плановые операции не становятся фактическими без подтверждения пользователя.

# 3. Главная продуктовая идея

## Основной USP

> **Понимайте свои деньги, а не просто записывайте расходы.**

Вторичный message:

> **Знайте, сколько денег у вас есть, на что они уже предназначены и сколько можно потратить прямо сейчас.**

Не позиционировать HarmoFin только как:

> «приложение для учёта расходов»

Это слишком generic и не отражает уникальность продукта.

---

# 4. Тон коммуникации

Стиль текста:

- простой;
- спокойный;
- уверенный;
- современный;
- без финансового жаргона;
- без агрессивного маркетинга;
- без обещаний, которых продукт не поддерживает.

Текст должен быть понятен человеку, который никогда не использовал envelope budgeting.

Не использовать чрезмерно рекламные формулировки вроде:

- «революция в финансах»;
- «победите бедность»;
- «гарантированно сэкономите»;
- «финансовая свобода за 30 дней».

HarmoFin должен ощущаться как спокойный и надёжный финансовый инструмент.

# 22. FAQ

ID:

`#faq`

Использовать accordion.

## Questions

### Что такое HarmoFin?

> HarmoFin — веб-приложение для управления личным и семейным бюджетом, которое связывает фактические движения денег по счетам с их назначением в конвертах и категориями расходов.

### Чем HarmoFin отличается от обычного учёта расходов?

> Он показывает не только баланс счетов, но и назначение денег и доступную сумму до следующей границы финансового периода.

### Нужно ли получать одинаковую зарплату каждый месяц?

> Нет. HarmoFin работает с фактически полученной суммой.

### Можно ли копить на отдельные цели?

> Да. Для этого используются накопительные конверты.

### Есть ли банковская синхронизация?

> Не в текущем MVP. Банковские интеграции предусмотрены для следующих этапов.

### Можно ли пользоваться с телефона?

> Да. Интерфейс должен адаптироваться под смартфоны и планшеты.

# 25. Визуальное направление

Использовать стиль:

- modern fintech;
- clean SaaS;
- premium but approachable;
- много свободного пространства;
- светлый фон;
- глубокий графитовый текст;
- один основной брендовый accent;
- мягкие карточки;
- тонкие borders;
- лёгкие shadows;
- крупные цифры;
- минимальный визуальный шум.

Не использовать:

- stock photos;
- фотографии семей;
- классические банковские «зелёные» градиенты;
- чрезмерно тёмный fintech;
- crypto-style neon gradients;
- перегруженные dashboards;
- 3D graphics без функционального смысла;
- большое количество иконок.

# 28. Animation

Использовать анимации только для усиления UX.

Разрешено:

- fade in;
- translateY;
- scale 0.98 → 1;
- number count-up;
- progress bar;
- timeline reveal;
- chart reveal;
- accordion animation.

Не использовать:

- бесконечные floating animations;
- тяжёлые parallax;
- continuous rotation;
- flashy transitions.

Учитывать:

```css
@media (prefers-reduced-motion: reduce)
```

При reduced motion:

- отключить entrance animations;
- отключить count-up;
- оставить статическое состояние.

# 33. Accessibility

Обязательно:

- semantic HTML;
- keyboard navigation;
- visible focus;
- accessible buttons;
- `aria-expanded` для FAQ;

Требования доступны соответствуют требованиям accessibility основного ТЗ.

# 34. Performance

Цель:

- быстрая первая отрисовка;
- минимизация JS;
- lazy loading тяжёлых визуальных компонентов;
- не загружать большие bitmap mockups, если их можно сделать CSS/SVG;
- использовать WebP/AVIF для растровых изображений;
- использовать SVG для иконок;
- не подключать тяжёлую chart library только ради одного-двух графиков.

Целевой ориентир продукта — открытие страницы примерно до 3 секунд при нормальном соединении.

# 35. Что важно для frontend implementation

Если проект реализуется на Vue 3:

- `<script setup>`;
- TypeScript;
- composables только там, где они реально необходимы;
- presentation components должны быть простыми;
- не использовать Pinia для статических данных лендинга;
- не создавать глобальное состояние без необходимости;
- не смешивать marketing-page UI с domain logic приложения;
- все mock data локализовать в отдельном module;
- использовать существующий router;
- использовать существующий design system проекта.

Если проект использует Quasar:

- использовать существующие Quasar primitives там, где это улучшает accessibility и consistency;
- не превращать маркетинговый лендинг в набор стандартных `QCard/QBtn` без дополнительной стилизации;
- внешний вид должен соответствовать HarmoFin Design System.

# 41. Важный принцип для агента

Не пытаться буквально копировать wireframe пиксель в пиксель.

Wireframe задаёт:

- структуру;
- визуальную иерархию;
- порядок блоков;
- смысл;
- content hierarchy;
- основные UI patterns.

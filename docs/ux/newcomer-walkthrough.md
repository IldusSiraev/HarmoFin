# Прохождение первого запуска глазами нового пользователя

Журнал наблюдений владельца при первом прохождении HarmoFin (модель Envelope v2.2) с чистого бюджета. Цель — чтобы человек, который ничего не знает о приложении, сразу понимал, о чём оно и что делать дальше. Ведётся сессией «UX-наблюдатель» (промпт: `docs/superpowers/prompts/ux-newcomer-walkthrough.md`). Записи на русском; код и идентификаторы — на английском.

## Как вести

- Одно наблюдение = одна запись `UX-NN`. Номера сквозные, не переиспользовать.
- Статус: `новое` → `обсуждается` → `решение согласовано` → `сделано` (с SHA) или `отклонено` (с причиной).
- Формулировка «что непонятно» — со слов владельца, без смягчений. «Как работает сейчас» — факт по коду, проверенный сессией.
- Предложений на каждое наблюдение 1–3, с рекомендацией. Код не менять без согласования.

## Шаблон записи

```
### UX-NN. Короткое название
- Экран / шаг: …
- Что видит пользователь: …
- Что непонятно (слова владельца): …
- Как работает сейчас (проверено по коду): …
- Почему это путает новичка: …
- Варианты решения: 1) … 2) … (рекомендация: …)
- Решение владельца: …
- Статус: новое
```

## Наблюдения

### UX-01. Окно шаблона: «Обязательные расходы» с одним пунктом, конверты разбросаны по трём разделам

- Экран / шаг: чек-лист «Начало работы» → «Настроить базовый шаблон» (и Настройки) → окно «Базовый шаблон бюджета».
- Что видит пользователь: разделы «Цикл», «Категории», «Конверты периодов» («Первый период», «Второй период»), «Обязательные расходы» (один пункт «Обязательные» с пометкой «Будет создан»), «Накопления по желанию».
- Что непонятно (слова владельца): раздел «Обязательные расходы» с единственным пунктом «Обязательные» и пометкой «Будет создан» непонятен. Предложение: общий раздел «Конверты», внутри «Первый период», «Второй», «Обязательные», «Накопления».
- Как работает сейчас (проверено по коду): `TemplatePreviewSheet.vue:518` «Конверты периодов» (два периодных, с целью и «Укажу позже»); `:617` «Обязательные расходы» — заголовок про платежи, а внутри строка с именем конверта; `:652` «Накопления по желанию» (чекбоксы). Все четыре вида — конверты в модели v2.2 (§5), но называются по-разному. Заголовок «Обязательные расходы» + подсказка про аренду/кредиты создают ожидание списка платежей; в шаблоне платежей нет (они создаются отдельно, на «Планах», и UI создания планов пока нет — open-decisions §1.3).
- Почему это путает новичка: слово «конверт» появляется только в «Конверты периодов»; «Обязательные» выглядит как отдельная сущность или список расходов, а «Будет создан» не объясняет, что создаётся (конверт-копилка под платежи, пустой, без сумм).
- Варианты решения: 1) (текст + разметка, один компонент) один раздел «Конверты» с короткой подсказкой «Конверт — назначение денег, а не отдельный кошелёк», внутри подзаголовки-группы: «На обычные траты (по периодам)» → Первый/Второй период; «Обязательные платежи» → строка «Обязательные» + пояснение «Сюда назначаются деньги на аренду, ЖКХ, кредиты. Сами платежи добавите позже на странице «Планы»»; «Накопления (по желанию)». 2) Минимально: оставить разделы, переименовать «Обязательные расходы» → «Конверт для обязательных платежей» и добавить пояснение под строкой. 3) Дополнительно заменить «Будет создан» на «Будет создан (пустой)» только для конвертов, т.к. сумм шаблон не назначает. Рекомендация: вариант 1 (+ пометка из 3). Цена: только `TemplatePreviewSheet.vue` и его тест; API и тексты статусов в других местах не затронуты. Нужно проверить, что `data-testid`/`aria-label` разделов не используются в e2e.
- Решение владельца: «делаем», вариант согласован.
- Статус: сделано (f476460)

### UX-02. Окно шаблона: заголовки групп мельче, чем их пункты (инверсия иерархии)

- Экран / шаг: окно «Базовый шаблон бюджета», раздел «Конверты» (после UX-01).
- Что видит пользователь: заголовок группы «Обязательные платежи» набран мельче, чем пункт «Обязательные» под ним; «Накопления по желанию» мельче, чем названия накоплений («Автомобиль», «Отпуск»).
- Что непонятно (слова владельца): раздел мельче своего пункта, поэтому «Обязательные» кажется главнее; то же у накоплений.
- Как работает сейчас (проверено по коду): `TemplatePreviewSheet.vue`, стили: `__heading` (h3) и `__name` (пункты) — `--hf-font-size-body` (1rem), оба 600; `__subheading` (h4, введён в UX-01) — `--hf-font-size-small` (0.875rem), 600. Итог: пункт (1rem/600) ≥ заголовок группы (0.875rem/600). Моя правка UX-01 ввела h4 мельче пунктов — это дефект именно этой правки.
- Почему это путает новичка: размер и вес читаются как уровень важности; заголовок, который не крупнее содержимого, не работает как заголовок.
- Варианты решения: 1) (только CSS) h3 «Конверты» = body 1rem/700 с более плотным цветом, h4 = body 1rem/600, а названия пунктов (`__name`) — body 1rem/**500** (medium), чтобы пункт был явно легче группы; 2) пункты уменьшить до small 0.875rem/500, группы оставить 1rem/600 (самый явный контраст, но мельче читаются суммы/названия); 3) добавить к h4 цвет `text-muted` + uppercase-«кикер» как на дашборде (`dashboard-kicker`) — заголовок группы как метка, а пункты крупнее; сильнее меняет стиль. Рекомендация: вариант 1 (иерархия за счёт веса и цвета, шрифт не дробим). Цена: только CSS в одном компоненте; `__name` используется и в разделе «Категории», проверить, что не ломается.
- Решение владельца: «делаем», вариант согласован.
- Статус: сделано (f476460)

### UX-03. Окно шаблона: чекбоксы «Укажу позже» слишком крупные и забирают акцент

- Экран / шаг: окно «Базовый шаблон бюджета», строки «Первый период» и «Второй период» (поле «Целевая сумма»).
- Что видит пользователь: большой чекбокс «Укажу позже» с высотой строки 44px и квадратом 1.5rem; визуально тяжелее самого поля суммы.
- Что непонятно (слова владельца): чекбоксы очень большие, нужно сделать минималистичнее, они забирают на себя много акцента.
- Как работает сейчас (проверено по коду): `.template-sheet__check` — 1.5rem × 1.5rem, `.template-sheet__check-row` — `min-height: 44px` (touch-цель). Те же классы у чекбоксов накоплений и «Создать новый вместо архивного». «Укажу позже» по умолчанию включён (`later: true`) и отключается при вводе суммы (`onTargetInput`).
- Почему это путает новичка: второстепенная опция («можно не вводить сумму») выглядит главнее поля; выделенный чекбокс в акцентном цвете притягивает взгляд.
- Варианты решения: 1) чекбокс 1.125rem (18px), подпись `small` и цвет `text-muted`; кликабельная область остаётся ≥44px за счёт padding у label (touch-цель не страдает); 2) заменить чекбокс на текстовую ссылку/«пилюлю» «Укажу позже» (переключатель-кнопка с `aria-pressed`) справа от подписи поля — минималистичнее, но меняет разметку и тесты; 3) убрать чекбокс совсем: пустое поле = «позже», подсказка под полем «Можно оставить пустым — укажете позже» (меньше всего элементов, но меняет модель `later` и тест). Рекомендация: вариант 1 (быстро, доступность сохраняется); вариант 3 — следующий шаг, если вариант 1 всё ещё громоздкий. Цена: 1 — CSS; 3 — компонент и тесты (серверный контракт не меняется: цель либо передаётся, либо нет). Замечание по доступности: визуально уменьшать можно, зону касания ≥44px и видимый focus-ring (`outline: 2px`) сохранять — `.claude/rules/ui-ux.md`.
- Решение владельца: «делаем», вариант согласован. (Пункт 3 из этого сообщения — крупный шрифт названий накоплений — записан в UX-02.)
- Статус: сделано (f476460)
